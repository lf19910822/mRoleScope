# Design

## Context

模型 Intent 是受约束的计划输入，但模型无法可靠推断未写入合同的数字默认值，也可能在类别值较多时只调用一个批次。最终 Draft 必须由服务端依据正式快照和趋势摘要确定性构建。

## Decisions

1. 定义 `DefaultRankingLimit = MaxCurves`，把默认数量写入 Intent 提示词和服务端归一化规则。
2. 在 `normalizeIntentForQuery` 中识别明确单项、明确“前 N 个”和复数/类别查询。对于未指定数量且模型给出任意不一致数量的复数查询，归一化为默认数量；明确单项和明确数量不改写。
3. 在 Draft 构建前计算候选缺失摘要，按最多 8 条组成批次，通过现有 Registry 补齐。所有补齐结果进入同一排序和失败处理路径；剩余工具预算不足时保留部分状态和警告。
4. 仅把成功摘要的候选从“待排名结果”中筛出；模型工具批次不再成为候选全集的隐式边界。
5. 合并候选时使用去重追加函数维护 `SubQueryIDs`。

## Boundaries

- 不改变用户可见 API 合同和最多 8 条曲线容量。
- 不让模型生成每日点位；服务端仍只读取安全聚合摘要。
- 补齐操作仍遵守单批 8、请求 20 次工具和请求超时。
