# Proposal

## Why

类别型问题“哪些数据库正在被使用？”在真实调用中被模型错误规划为 `ranking.limit: 1`，导致服务端只生成 Redis，遗漏同一类别内的其他有效数据库。现有提示词只说“使用产品默认数量”，没有把默认值写成可执行的合同；同时类别摘要由模型按批次选择，服务端没有补齐未查询的正式候选，无法保证排名覆盖完整候选集。

## What Changes

- 将未指定数量的多项类别/全范围趋势查询的产品默认数量明确为 8。
- 在服务端对模型返回的数量做语义兜底：复数“哪些/有哪些/全部”等查询不得被错误收缩为单项；明确单项或“前 N 个”仍保留用户要求。
- 对类别候选补齐全部正式值的趋势摘要，按真实指标在服务端确定性排序后执行数量和八条曲线容量限制。
- 继续保留单批最多 8 项、单次请求最多 20 次工具调用和局部失败最大努力交付。
- 修复合并候选时重复写入同一 `sub_query_id` 的问题，并增加回归测试和文档说明。

## Capabilities

### New Capabilities

- `category-trend-ranking`: 类别和宽范围趋势查询的默认数量、完整候选排名与确定性结果分配。

### Modified Capabilities

无。

## Impact

影响趋势 AI Intent 归一化、候选摘要补齐、Draft 构建、提示词合同、AI 评测回归和趋势开发文档。不会改变公开 Serving API 或数据库结构。
