# Proposal: Versioned AI JD Semantic Analysis

## Why

现有 JD 建模已能以可审计的确定性词典识别技术提及，却不能可靠表达候选人经验年限、最低学历、技术的必需/加分关系、任选逻辑和明示熟练度。这些语义需要外部中文模型辅助，但必须在 CVM 的算力与数据边界内控制成本、外发范围、可复现性和人工复核。

## What Changes

- 新增一个远端、版本化的 AI 语义解析能力：只分析已版本化的 `description`、`jobRequire`、`addition`，一次调用提取年限、最低学历、学历/年限条件分支、技术要求组、熟练度和词典外候选词。
- 将模型、提示词、严格 JSON schema、输入/片段契约、依赖的已发布技术提及配置和校验器冻结为不可变候选配置；当前受控资产为 `ai-jd-result-v4` 与 `ai-semantic-validator-v4`，结果以正文版本与 AI 配置联合缓存，候选经人工发起的受控操作发布，不覆盖历史。
- 首版及后续新工作只允许阿里云百炼 `qwen-plus` 非思考模式。既有 `qwen-flash` 配置、结果和审计工件保留为不可变历史，但不再创建 Flash 试跑、对照或运行入口。
- 在 CVM 内生成证据片段编号并校验模型输出的**结构、请求绑定和跨正文边界**；结构合格的模型语义结论是首期可持久化的模型投影，不以其业务正确性、角色判断或证据角色判断作为阻断条件。无法映射至已治理技术身份的 formal option 仅局部丢弃；无效证据引用仅局部移除，不能污染同一响应的其他可表示字段。
- 每个响应最多接收 3 个技术候选词；全系统同时处于待人工治理状态的不同候选词最多 500 个。达到上限时只忽略新的候选词，不影响该 JD 的其他结果。
- 增加试跑预算/重试/Token 上限、候选词典衔接、受控远端操作和无正文验收报告；外部调用或单条结构失败不得影响每日来源同步或其他 JD 工作。

## Capabilities

### New Capabilities

- `jd-ai-semantic-analysis`: 从版本化 JD 正文生成、校验、复核、版本化和发布远端 AI 语义结果，并安全衔接技术提及、词典候选和下游统计。

### Modified Capabilities

- None.

## Impact

- **Data:** 新增 AI 配置、工作项/运行、结构化结果、语义证据、条件分支、复核、用量与发布证明的前向兼容 PostgreSQL 模型；既有正文版本、确定性技术提及、词典和发布记录保持不变。
- **Runtime:** worker 增加独立 AI 分析子命令与无端口 Compose one-shot 服务；root-owned 运维入口只接受固定操作/确认语，不接收任意提示词、SQL、路径、模型或凭据参数。
- **External dependency:** 受控接入阿里云百炼 API；密钥只可存在于 CVM 的受控密钥位置，真实 JD 只在 CVM 进程与已确认的中国大陆模型服务间传输。
- **Testing and operations:** 合成测试覆盖 JSON/请求绑定、局部降级、坐标映射、候选词上限、重试、预算、版本/人工发布和脱敏；首次受控试跑固定为 5 份 Plus 工作、每项至多 3 次尝试，使用 `10,000` 输入 / `5,000` 输出 Token 档案和 `2.50` 元硬上限。人工复核保留为质量审计，不是语义发布门禁。
- **Out of scope:** 项目名称解析、标题/`jobSummary`/投递说明解析、任意多模型路由、自动启用词典外技术、面向访客的 API/页面/图表、在本地或 CI 保存真实 JD/模型请求/模型响应。
