# Design

## Context

规划器将基础上下文与 `IntentPromptV1` 发给模型，并为工具续轮追加用户消息。类别目录和值目录属于不同工具；现有续轮消息无论收到了哪一种工具结果都会声称候选范围已经确认。参见 proposal 和规格中的范围与证据要求。

## Goals / Non-Goals

**Goals:**

- 在实际模型请求中使用用户审阅的完整规划提示词，并验证文档与运行时内容一致。
- 消除类别发现阶段未经证据支持的范围确认提示。

**Non-Goals:**

- 不改动工具执行、最终 Intent 的范围校验或单次摘要后结束工具轮次的现有行为。
- 不声称提示词可保证模型遵守范围或完成跨批次读取。

## Decisions

1. 将规划正文放入 `internal/aitrend/assets` 并通过 `go:embed` 加载，继续在请求中组合现有基础上下文。正文可保留审阅文档中的 Markdown 字符，避免 Go 原始字符串中的反引号转义；测试直接比较审阅文档的规划代码块与实际模型提示词，防止再次偏离。
2. 将尚无趋势摘要时的续轮说明改为根据用户问题和现有工具结果判断范围；需要时继续查询类别值或正式值，再读取摘要。保持工具失败处理和已有摘要后的关闭逻辑，避免扩大为编排改造。
3. 在模拟 Qwen HTTP 请求边界验证首轮规划内容和仅有类别目录时的续轮提示，而不把固定模拟模型响应当成真实模型正确率证据。

## Risks / Trade-offs

- [模型可能无视提示或无法表达跨维度条件] → 保留现有 Schema、正式值校验和工具预算，审阅文档继续明确没有新增应用侧范围锁定。
- [已有摘要后不再开放工具，可能无法逐批覆盖类别] → 保持现状并记录限制；跨批编排和真实模型复评需独立安排。
- [提示正文与人工审阅稿分离] → 用测试比较两者，防止只修改一方后无声漂移。
