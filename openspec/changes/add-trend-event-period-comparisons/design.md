# Design

## Context

现有 Serving 趋势读取已经具备以下事实边界：按 `Asia/Shanghai` 选择每日最终成功发布、区分完整零值与不可用日期、按完整正式维度解释读取历史、支持一个完整曲线条件、并复用趋势下钻读取岗位历史详情。现有前端趋势状态使用独立曲线请求、请求代次隔离和约十分钟 `sessionStorage` 聚合缓存。

本变更需要在这些边界上增加周期事件读取，而不是重建一套岗位历史或为每个曲线条件创建快照。具体决策以同目录的开发指导和决策文档为准；本设计说明实现这些决策的技术结构。

## Goals / Non-Goals

**Goals:**

- 从可信历史观察临时计算四类周期事件：进入曲线、曲线内修改、离开曲线、重新上线。
- 让折线读取、事件统计读取和事件下钻读取语义分离，同时保证三者使用相同的曲线条件与正式解释。
- 支持本周、本月、本季度、本年度和自定义范围的等长环比/同比，并返回实际日期窗口。
- 处理历史基线、基线前合法零值、缺失日期静默跳过、全周期缺失合法零值、未结束周期和人工修补。
- 在前端提供单曲线表格、明确的曲线选择边界、状态反馈、隔离缓存和竞态保护。
- 用 TDD、HTTP 契约、Serving 集成、浏览器视觉和性能验收覆盖全部决策。

**Non-Goals:**

- 不新增按筛选条件的快照表、事件物化表、预计算表或改变 ODS/DWD/Serving 数据分层。
- 不修改现有折线接口的响应结构，不将事件数据嵌入折线请求，不用当前岗位结果回填历史。
- 不首期提供学历或工作年限的事件统计数字；不新增事件次数指标。
- 不新增另一套岗位列表、详情页面或独立下钻容器。
- 不把缺失日期渲染为事件、零值日期节点或用户可见的数据质量提示。

## Decisions

### 1. Build a trusted observation stream, then classify transitions

新增内部只读事件聚合器，先从现有历史事实选择观察流，再做纯函数分类：

1. 按自然日选每个观察范围当天最后一次成功发布；沿用现有最终发布选择逻辑。
2. 每个岗位按日期去重，保留活动状态、来源 metadata/body 版本身份和参与正式维度匹配所需的历史结果。
3. 删除没有可信最终观察的日期；不制造缺失日期的零值观察。
4. 对每个岗位按可信观察日期排序，比较相邻可信观察；跨缺失日的转移归属到后一个可信观察日。
5. 使用现有历史修改判定和生命周期判定识别事件，并以 `job_id + event_type + period` 去重。
6. 只把事件日期落入目标周期的事件计入该周期。

这保留“缺失日期静默跳过”与“后一个可信观察日归属”两条决策，同时避免将周期末曲线存量误当成事件。

### 2. Reuse lifecycle and modification semantics, not a second change detector

事件分类器复用现有岗位历史使用的来源 metadata/body 版本变化、确认下线和重新上线语义。分类优先级固定为：

1. 前一可信观察为确认下线、当前恢复有效：`重新上线`，不再分类为进入；
2. 当前从有效变为确认下线且前一有效观察匹配曲线：`离开曲线/确认下线`；
3. 当前为有效且发生既有 JD 修改：根据前后曲线归属分别为修改进入、曲线内修改或修改移出；
4. 岗位在历史流中首次有效观察且匹配曲线：`进入曲线/历史基线进入`；
5. 非事件的存量观察不计入事件。

纯分类函数同时返回内部原因枚举，公开响应只返回必要的用户-facing 原因标签。周期级聚合对同一岗位同一事件类型只保留一次，但允许同一岗位在同一周期出现于不同事件类型。

### 3. Use the same formal curve predicate as the line reader

事件聚合不读取当前岗位清单的最新维度结果。它调用/复用各趋势维度已有的历史匹配构造：

- 技术关键词按正式 technology identity 和完整发布 configuration；
- 岗位族保留 `include_secondary`；
- 项目按历史正式 `project_key`；
- 工作地点按历史结构化地点；
- 学历、工作年限保留趋势查询合法性，但事件统计路由拒绝返回数字。

正式维度发布身份作为事件计算输入和缓存不透明 fingerprint。不存在可用正式解释时，返回安全的不可比状态；普通缺失日期和全周期缺失仍按静默/合法零值规则处理。

### 4. Resolve comparison windows on the server

新增事件统计读取能力接收与趋势兼容的曲线条件、自然范围或自定义范围。服务端依据上海自然日和最近最终成功观察解析：

- 当前窗口：自然周期起点至最近最终成功观察日；自定义范围使用请求的闭区间；
- 环比窗口：与当前窗口等长的前一窗口；
- 同比窗口：去年同一相对窗口；
- 全部历史：返回需要具体时间范围的安全状态，不执行事件聚合。

服务端返回三个实际日期范围和每个事件的当前/环比/同比 count、rate。客户端不重新推导窗口，避免前后端在未结束周期、月份长度或时区上的口径漂移。变化率在服务端按 `(current - comparison) / comparison` 计算；分母为零返回 nullable rate，前端显示 `-`。

基线前窗口不要求历史行：事件贡献为合法零；基线日的匹配有效岗位产生历史基线进入。普通缺失日从观察流静默移除；整个窗口无观察时四类 count 为零。

### 5. Keep separate HTTP seams

保持现有接口：

- `GET /api/v1/job-trends`：只读折线及其已有 coverage/freshness。
- `GET /api/v1/job-trends/drilldown`：继续支持日期节点；扩展为可选的事件模式，要求周期起止和事件类型时走事件语义，不影响旧节点参数。

新增：

- `GET /api/v1/job-trends/events`：读取四类周期事件统计。

HTTP 层负责重复参数、自然日期、曲线条件、事件类型和范围的安全校验；Serving 层负责可信观察选择、正式条件和事件聚合。公开 contract 只携带展示数据、实际周期、可用状态和安全错误，不携带 job/source/version/audit/repair 字段。

### 6. Reuse the existing drill-down container with an event mode

前端把日期节点和事件下钻作为同一容器的两种读取模式：

- node mode：保持当前日期、count、condition、title、page cache key；
- event mode：新增 period start/end、event type、condition、title、page key。

事件列表使用相同分页、标题搜索、岗位状态、历史/最新详情和返回行为。标题上下文由事件名称、曲线 label、实际周期组成；进入和离开原因在列表内以安全的业务标签区分。不可比单元格不打开容器，合法零值可以打开空结果。

### 7. Add one selected-curve state and isolate event cache

趋势页面保持折线 rows/visibility/configuration 与新增 `selectedEventCurveId` 分离：

- 首次有已应用曲线时选第一条；删除当前曲线后选剩余第一条；无曲线不显示表格；
- 曲线本身、曲线卡片和左右箭头只改变 selected state；
- 图表具体 data point 只触发既有日期下钻，阻止事件冒泡改变 selected state；
- 支持维度异步读取事件统计，教育/经验显示“开发中”且不请求。

事件缓存另用独立 storage key 和内存索引，至少包含规范化曲线条件、三个实际窗口、事件语义版本和正式解释 fingerprint；只保存统计数字、周期、curve label 和安全状态，不保存岗位 ID、标题、正文或内部版本。沿用短期约十分钟生命周期、显式刷新绕过和 freshness mismatch 清理。没有命中缓存时先清空旧表格数字；用 request generation/AbortController 只接受最后一次选择的结果。

### 8. Failure and loading states are local

折线、已有日期下钻和事件表各自拥有请求生命周期。事件表状态包括 `development`、`loading`、`ready`、`error`、`unavailable` 和合法空值展示：

- loading 保留表头/周期标签，使用轻量骨架，不显示旧曲线数字；
- error 显示“统计暂不可用”和重试，重试只请求事件接口；
- unavailable 显示“暂无可比数据”，不可下钻；
- ready 的四行指标即使为零也完整显示，零值可下钻为空列表；
- 任何状态不展示后端错误、接口、请求 ID、版本、审计或修补细节。

### 9. Test-first and acceptance gates

实现顺序采用红—绿—重构：先为纯事件分类/周期窗口/公开 contract、HTTP 参数、前端事件状态和交互边界写失败测试，再实现最小行为。验证覆盖：

- Go 单测：最终观察选择、基线、缺失日、全周期缺失、生命周期/修改分类、周期去重、比较率；
- Serving 数据库集成：四类维度正式匹配、完整发布、历史修补一致性和真实事件下钻；
- HTTP/OpenAPI：独立 endpoint、错误映射、字段泄露回归；
- Vitest/component：单曲线选择、箭头、状态、缓存键、旧响应隔离、点/曲线点击边界；
- Playwright：桌面和 390px 表格可读、下钻上下文、开发中/失败/零值状态；
- `git diff --check`、Go/Vitest/type-check/build 及严格 OpenSpec 校验。

性能验收不预设固定毫秒数：必须证明折线先可用、事件请求不阻塞旧功能、只请求当前曲线、失败可独立重试、返回看板复用有效缓存。若按需聚合实测成为明显瓶颈，另行提出经测量支持的时间区间缓存/优化设计，不在本变更中提前物化所有筛选条件。

## Risks / Trade-offs

- [事件聚合读取历史范围较大，可能慢于单日趋势] → 使用只读事务、按目标窗口限制观察、复用已有索引/最终发布 CTE，并在性能验收中测量；不以猜测提前建表。
- [跨缺失日的状态变化不代表精确发生日] → 只归属后一个可信观察日，不声称缺失日发生事件，也不向用户提示内部缺口。
- [正式解释版本变化导致历史数量变化] → line/event 共用同一完整正式发布 fingerprint，并使两类缓存一起失效；页面不暴露版本。
- [事件表和折线响应竞态] → 分离请求控制器和 generation guard；事件旧响应不得覆盖当前曲线，折线请求不受事件失败影响。
- [统计数字与下钻列表在数据更新后短暂不一致] → 下钻沿用既有 count consistency notice；保留真实服务结果，不填充或截断列表。
- [大量事件结果进入浏览器缓存] → 只缓存聚合数字和安全标签，设置短期生命周期，独立 key，不缓存岗位列表或正文。

## Migration Plan

1. 先部署后端只读事件统计能力和事件模式下钻；旧趋势接口与旧下钻参数保持兼容。
2. 部署前端表格、选择状态和独立缓存；旧缓存无法解析时静默丢弃，不影响折线恢复。
3. 运行 focused tests、严格 OpenSpec 校验、构建和桌面/390px 视觉验收；事件表失败时确认折线仍可用。
4. 按现有受控发布手册发布；不需要数据库迁移、历史回填或人工建立事件快照。
5. 若发布后需要回滚，先回滚前端事件表调用，再回滚后端新路由；旧 `/job-trends` 和日期节点下钻保持可用。回滚不删除历史事实或缓存以外的数据。
