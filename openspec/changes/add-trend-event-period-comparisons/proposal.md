# Proposal

## Why

现有趋势看板能够展示某条曲线在每日最终成功观察中的岗位存量，但无法回答一个周期内有多少岗位进入、修改、离开或重新上线，也无法把这些变化与上一个等长周期及去年同期进行比较。招聘分析需要区分“岗位存量”和“岗位事件”，因此需要在不为每个筛选条件物化快照的前提下，复用现有历史事实和正式维度解释按需计算周期事件。

本变更同时解决事件统计与现有趋势交互之间的边界问题：折线优先、统计表异步、事件下钻复用现有岗位阅读链路，并将缺失日期、历史基线、未结束周期和人工修补纳入统一口径，避免产品实现遗漏已确认的细节。

## What Changes

- 新增按曲线条件和周期临时计算的四类事件统计：进入曲线、曲线内修改、离开曲线、重新上线。
- 事件按周期内去重岗位数统计；严格复用现有岗位历史修改判断、每日最终成功观察和正式维度解释。
- 以当前历史覆盖第一天作为合法基线；基线日匹配岗位算进入曲线，基线日前周期事件数量为合法 `0`，不因基线阻断统计。
- 缺失日期静默跳过，不补零、不造事件、不提示；跨可信观察的转移归属后一个可信观察日；人工修补后与正常观察完全一致参与计算。
- 支持本周、本月、本季度、本年度和自定义范围的当前周期、等长环比周期及去年同期同比周期；全部历史不显示同比环比表。
- 新增独立事件统计读取能力，保持现有趋势折线接口和折线优先加载路径不变。
- 在趋势图下方增加单曲线事件统计表：支持技术关键词、岗位族、项目、工作地点；学历和工作年限显示“开发中”。
- 表格展示当前周期数、环比周期数及变化率、同比周期数及变化率，并显示三个实际日期范围；合法零值、分母为零、正式口径不可用分别处理。
- 表格当前曲线支持曲线本身、曲线卡片及表格左右箭头切换；点击具体数据点只打开既有日期下钻，不切换表格曲线。
- 事件数量下钻扩展既有趋势下钻读取语义，复用现有抽屉、岗位列表、分页、详情和返回行为，并按事件原因细分进入/离开结果。
- 折线缓存与事件统计缓存隔离；统计表只加载当前曲线，异步请求失败可独立重试，不影响折线及原有下钻。
- 增加覆盖后端聚合、公开 API、前端状态/cache/交互、错误状态、事件下钻、TDD、视觉验收和性能验收的完整测试与验收任务。

## Capabilities

### New Capabilities

- `job-trend-event-statistics`: 按历史曲线条件和比较周期计算并返回四类去重岗位事件及同比环比数据。
- `job-trend-event-drilldown`: 从事件统计数量读取周期内真实发生该事件的岗位，并复用现有历史岗位详情链路。
- `job-trend-event-dashboard`: 在趋势看板展示单曲线事件统计表、周期标签、状态、切换交互和隔离缓存。

### Modified Capabilities

无。仓库当前没有已发布的主线 `openspec/specs`；本变更以历史趋势看板、趋势服务、趋势下钻和自定义范围 change spec 作为兼容基线，不直接修改历史 change artifacts。

## Impact

- 后端：`internal/jdserving` 增加周期事件读取、事件下钻查询和公开契约；`internal/httpserver` 增加独立路由、参数校验和 OpenAPI 契约。
- 前端：趋势 dashboard state、API client、事件统计表、曲线选择边界、事件下钻上下文、sessionStorage 缓存和响应式视觉验收均受影响。
- 数据：不新增按筛选条件的快照、物化事件表或预计算结构；只读已有 Serving 历史、版本事实和正式维度结果。
- 性能：折线接口保持独立并优先完成；事件统计按当前曲线异步读取，只有测量证明确有必要时才评估时间区间缓存等进一步优化。
- 兼容性：现有折线、日期节点下钻、岗位详情和全部历史行为保持可用；新接口失败不得阻断旧功能。
