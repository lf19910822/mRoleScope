# Proposal

## Why

岗位浏览已经能展示最新 JD，但无法回答“某项技能、地点或岗位族的需求在一段时间内如何变化”。
现有 SCD2 与每次成功发布的 Serving 成员事实已具备可恢复历史快照的基础，需要以严格、可复查
且不泄露内部建模细节的方式提供趋势看板。

## What Changes

- 新增只读的历史趋势 Serving 能力：按 `Asia/Shanghai` 自然日、每个观察范围当天最后一次成功
  发布，返回单条已配置曲线的日度去重 JD 数或事实缺口。
- 让趋势查询统一使用最新**已发布且全量覆盖**的确定性结构化口径；新解析版本在全部可恢复
  历史正文处理完成前不得成为趋势看板的正式口径。原始快照不复制、不改写。
- 新增 Vue 趋势看板：支持六种维度、最多八条曲线、独立更新、真实断点、固定自然日期范围与
  仅“全部历史”可缩放／平移的图内交互。
- 增加短时浏览器聚合结果缓存与显式刷新，保留配置和阅读位置，同时不向页面暴露词典、解析、
  覆盖率、版本或审计细节。
- 使用 Apache ECharts 与 `vue-echarts`；外围继续采用现有 Vue 3、TypeScript、Naive UI 和主题。

## Capabilities

### New Capabilities

- `job-trend-serving`: 安全、可复查地从已发布 SCD2 快照和完整正式维度结果返回单条岗位趋势。
- `job-trend-dashboard`: 让用户配置、阅读、缓存和交互最多八条历史岗位趋势曲线。

### Modified Capabilities

- None.

## Impact

- Go 路由、OpenAPI、趋势查询／Serving 边界，以及可能需要的追加式版本发布元数据；不改变
  ODS 采集、`collection_runs` 发布或公开网络边界。
- 确定性维度重解析的正式发布门槛，确保趋势使用的最新已发布规则覆盖全部可恢复历史正文。
- Vue 路由、左侧导航、类型化 API 客户端、ECharts 依赖、趋势看板组件及其测试。
- 本地与 CVM 的只读性能测量；只有“全部历史 + 8 条曲线”超过 2 秒才另行提出预计算 Serving
  或每日物化任务，未经批准不增加该类存储或运行流程。
