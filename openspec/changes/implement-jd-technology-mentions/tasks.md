# Tasks

## 1. 分离来源元数据与正文内容版本

- [x] 1.1 新增向前兼容的 PostgreSQL 迁移，建立来源元数据版本、正文内容版本、逐运行版本引用和正文内容期；保留既有 `jd_versions`、`run_jobs`、可见期、旧内容期及 COS 引用，验证空库迁移、已初始化库升级和必要外键/唯一约束均通过。
- [x] 1.2 实现元数据白名单与类型化空值规范化、三正文分区规范化、业务指纹和每字段文本哈希；以合成 JSON 单元测试验证标题/地点/来源标签变化、数组顺序变化、`absent`/`null`/空值差异、正文变化和排除字段变化的版本结果。
- [x] 1.3 实现远端数据库内的幂等基线回填与安全覆盖摘要，将既有已发布观察映射到新版本引用和正文内容期；以 PostgreSQL 集成测试验证历史行/COS 引用未删除、重复回填无重复记录且输出不含正文。

## 2. 词典、匹配与证据模型

- [x] 2.1 新增技术身份、词典版本、词典规则与候选状态的数据模型，支持 `enabled`、`conditional`、`candidate`、规则摘要和人工决策留痕；将 v0.1 映射转换为待审核的结构化种子，验证未显式批准的规则不能启用或生成提及。
- [x] 2.2 实现首轮确定性匹配器，只处理 `description`、`jobRequire`、`addition` 中已启用的精确规则，并支持规则级大小写、边界和最长重叠匹配；以合成用例验证相似名称、复合名称、别名归一化、宽泛方向词排除及不推断隐含生态技能。
- [x] 2.3 实现 UTF-8 字节索引到 Unicode 码点半开区间的集中转换与远端区间校验；以含中文、ASCII、标点、组合字符、相邻命中和多处命中的合成测试验证 `0 ≤ start < end`、字段独立从零计数及别名一致性。
- [x] 2.4 新增分析结果、岗位级提及和多条证据记录的持久化模型，确保 `(正文版本, 解析器版本, 词典版本)` 可复用、每项技术每个结果只计一次且保留所有证据；以 PostgreSQL 集成测试验证重复运行不重复写入和非法证据拒绝发布。

## 3. 分析运行、重算与复核

- [x] 3.1 实现数据库支持的待处理队列、分析运行状态、配置级锁和安全审计，使分析器只读取远端 PostgreSQL 正文版本并独立消费新正文；验证分析失败不会回滚已发布同步、待处理项可重试且不重新访问来源接口。
- [x] 3.2 将同步发布事务切换为写入新版本模型和逐运行引用，并仅在新增/变化正文时创建下游待处理项；以合成同步集成测试验证元数据单改不创建正文版本或待解析工作、正文修改和重新出现保留稳定岗位身份与历史。
- [x] 3.3 实现解析器/词典版本候选重算、历史正文全量入队、运行期间新增正文追赶和原子发布指针切换；以集成测试验证新旧配置不混用、失败候选保留旧发布版本、相同配置重跑幂等。
- [x] 3.4 实现独立人工复核记录和远端受控复核查询，支持正确/错误/暂不确定、错误分类、复核人/时间与精确版本关联；验证复核不覆写自动结果且不会自动继承到其他正文或规则版本。
- [x] 3.5 为分析审计、错误处理和操作输出复用严格的字段白名单、限长和脱敏逻辑；以模拟正文、密钥和上游错误的测试验证数据库、容器日志、CI 输出和错误堆栈均不泄露原文或凭据。

## 4. 受控远端分析执行

- [x] 4.1 为现有 worker 增加显式分析子命令和无端口、仅 backend 网络的 Compose one-shot 分析服务；验证镜像可完成合成分析流程、`docker compose config` 不给分析服务分配 edge 网络/端口/原始数据挂载，且普通 API 启动不自动运行分析。
- [x] 4.2 新增 root-owned 分析 helper、独立 systemd one-shot 单元和固定的 `run-pending-analysis` 运维操作；在同步成功后以 best-effort 方式启动分析，验证分析失败时同步 service 仍以源数据成功退出、分析工作保留待处理且不允许任意命令/路径/密钥参数。
- [x] 4.3 扩展部署 bootstrap、受控发布记录、运维工作流 allowlist 和静态检查，使分析镜像仍受同一不可变 digest/revision 验证；验证伪造镜像、未授权操作和不安全服务配置被拒绝，现有同步入口和 timer 不受回归影响。
- [ ] 4.4 编写远端运行与验收指导：基线回填、候选词典审核、初次分析、远端人工抽检、发布/回退和待处理恢复；验证文档不包含真实 JD、正文片段或凭据，且每个操作都对应受控实际入口。

## 5. 集成验收与交付门禁

- [x] 5.1 扩展 CI 以执行新迁移、sqlc 生成一致性、Go 单元/集成测试、合成词典/正文测试、部署脚本静态检查和 worker 镜像构建；验证干净 CI 不请求真实来源、不访问真实 COS 且不输出正文。
- [ ] 5.2 在 CVM 以受控操作执行数据库升级和基线回填，仅核验安全行数、版本/队列/审计状态及既有同步连续性；验证每日同步继续在 02:00 运行，分析不可用时仍不影响源数据归档和发布。
- [ ] 5.3 将经人工批准的首版规则设为候选配置，执行远端全量分析并完成发布前门禁：每个实际命中的启用规则至少一条复核、高风险边界/多处命中复核、无命中正文抽检、坐标/幂等/脱敏检查；验证仅在全部通过后原子发布配置，输出只含汇总与稳定标识。
- [ ] 5.4 用受控故障和修复演练验证分析失败隔离、待处理恢复、词典升级全量重算、旧版结果保留和发布指针回退；记录不含原文的验收结论与容量增长摘要。
