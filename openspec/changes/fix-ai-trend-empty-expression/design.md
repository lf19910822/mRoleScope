# Design

## Context

意图合同目前只要求 `expressions` 数组至少有一个元素，允许元素本身为空或使用通配符。`candidateGroups` 已有宽泛表达式扩展逻辑，但空字符串和 `*` 没有被识别为宽泛表达式；规划器随后把它发送给 `rank_values`。参见 proposal.md 和 `ai-trend-broad-value-fallback` 规格。

## Goals / Non-Goals

**Goals:**

- 在 Serving 正式筛选值范围内处理空表达式，并复用现有摘要评分、稳定排序和曲线限制。
- 不发送空排序参数，减少无效工具调用。
- 保留具体表达式的现有匹配语义。

**Non-Goals:**

- 不让 AI 生成新的正式值，不修改数据库或词典。
- 不改变模型合同、HTTP 事件协议或前端草稿组件。
- 不放宽 20 次工具调用、8 条曲线或排除条件边界。

## Decisions

### 1. 在确定性 resolver 中将空表达式视为宽泛查询

`isBroadExpression` 对归一化后为空、`*`、`all` 以及“全部/所有 + 维度”表达式返回 true，使现有 `resolver.Values[dimension]` 全量候选分支生效。候选仍标记为扩展推荐，并由后续摘要分数决定顺序。

### 2. 规划器跳过空/宽泛 rank

规划器只为具体表达式生成 `rank_values`；空、通配和“项目/岗位族/哪些项目”等宽泛表达式直接依赖 `list_available_values` 与趋势摘要。这样不会产生无效参数，也不额外消耗工具调用配额。

### 3. 通过 runner 测试覆盖端到端候选生成

测试使用项目正式值 fixture 和趋势摘要 reader，验证空表达式最终产生有序草稿、排除条件生效，并检查事件序列不包含空的 rank 参数。

### 4. 在提示词中固定通配表达

提示词直接给出 `expressions: ["*"]` 的宽泛类别表示，并明确禁止空字符串。服务端仍保留空值兜底，以兼容旧模型或其他合法历史请求。

## Risks / Trade-offs

- [宽泛维度可能返回的正式值很多] → 仍使用现有候选、批量请求、20 次工具和 8 条曲线上限，并明确标记扩展推荐。
- [模型继续输出空表达式] → 不再导致 0 条结果；确定性服务层负责最大努力兜底。

## Migration Plan

1. 更新 resolver 和工具规划逻辑，补充单元及 runner 回归测试。
2. 通过受保护 `main` 发布。
3. 用“哪些项目的岗位最多？”真实请求验证草稿和应用结果；若失败可回退应用镜像。
