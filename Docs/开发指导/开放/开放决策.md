# mRoleScope 开放决策

> 文档状态：代码层实施与本地验收完成；公网 DNS、CVM、安全组和真实邀请码仍未执行
> 更新日期：2026-11-12

## 目标

首轮开放用于真实体验验证，邀请 HR、面试官、亲戚朋友访问并反馈网站的实际使用体验。首轮不以测定最大并发承载能力为目标，也不据此宣称系统具备某个并发容量。

## 已确认决策

### 访问对象与发放方式

- 采用分批发送方式，首批人数暂不设固定上限；根据实际体验逐步扩大范围。
- 使用一个共享邀请码，不建立用户账号、分级权限或个人身份审计。
- 邀请码不设过期时间；邀请码泄露后通过整体更换邀请码处理，旧邀请码失效。
- 通过邀请码后，当前浏览器保持登录 3 天；登录态到期、清除 Cookie 或邀请码更换后需要重新输入。

### 访问边界

- 仅邀请码输入页和邀请码校验接口允许匿名访问。
- 岗位列表、岗位详情、趋势看板、业务静态资源及所有业务 `/api/` 请求均必须通过访问门禁。
- 不依赖前端隐藏保护数据；服务端或 Web Edge 必须拒绝未通过门禁的业务请求。
- 数据库和内部 API 不直接暴露公网，公网只提供统一的 HTTPS Web Edge 入口。

### 正式入口

- 首轮只使用 `https://mrolescope.com/`。
- 不开放 `www.mrolescope.com`。
- 不支持裸 IP 作为产品入口。
- HTTP 仅用于跳转 HTTPS（以及必要的证书签发挑战路径）。

### 开放周期

- 采用持续开放模式，不按固定时间窗口反复启停。
- 受邀者可以错峰访问，适合 HR、面试官和亲友分批体验。
- 发现明显故障、资源异常、邀请码泄露或需要进行不兼容发布时，维护者可以人工停止 Web Edge、撤销入口或更换邀请码。
- 持续开放不代表承诺无限并发；首轮仍以真实体验观察为目标。

### 日志边界

- 保留最小运维日志，用于性能观察、安全限流和故障排查。
- 可记录请求路径、状态码、响应耗时、错误和限流事件；必要时保留来源 IP。
- 不记录邀请码、登录 Cookie、Authorization、请求体或岗位正文。
- 不建立用户账号、访问者档案、邀请码使用者归属或岗位浏览行为分析。
- 运维日志不写入业务数据库；日志用途限于运行维护和安全防护，不构成用户身份审计。

### TLS 证书方案

- 采用 Let's Encrypt 免费 DV 证书，不购买腾讯云付费证书。
- 首轮只申请 `mrolescope.com`，不申请 `www.mrolescope.com` 或通配符证书。
- 优先采用 HTTP-01 域名验证；域名解析到 CVM 且公网 `80` 端口可访问挑战路径后再签发。
- 在 CVM 上配置 root 受控的自动续期任务；续期成功后重新加载 Web Edge。
- 将证书到期检查和续期失败发现作为持续开放的运维责任。
- 不把 DNS API 凭据放到 CVM；不使用 DNS-01 作为首轮默认方案。
- 证书私钥只保存在 CVM 的 root 受控 TLS 目录，不进入仓库、镜像或聊天记录。
- 接受在 CVM 上增加 root 受控的 ACME 自动续期任务，并将证书续期视为持续开放的运维责任。

### 首发顺序

- 首次签发证书前，先将 `mrolescope.com` 的 DNS 指向 CVM；此时不发送邀请码。
- 首次签发优先使用临时 root 受控 ACME HTTP-01 验证流程，Web Edge 不承载业务页面。
- 证书链和私钥成功写入受保护 TLS 目录并完成权限检查后，才启动 Web Edge。
- Web Edge 启动后依次验收 HTTPS、邀请码校验、3 天登录态、业务 API、裸 IP 拒绝和移动端/桌面端页面。
- 全部验收通过后，才向第一批受邀者发送邀请码。
- 后续续期使用预留的 ACME challenge 路径；续期失败保留旧证书并触发运维告警，不因单次续期失败删除可用证书。

### 最低安全边界

- 必须使用 HTTPS。
- 邀请码只能以不可逆哈希形式保存，不写入前端代码、URL、日志、镜像或版本库。
- 保留登录失败限流和安全 Cookie 属性；这些是凭据保护措施，不构成额外的用户身份审计或权限系统。
- 首轮只观察真实体验，不进行未经控制的公网压力测试。

### 用户体验与实现边界

- 用户首次访问正式入口时只看到邀请码输入页。
- 邀请码验证成功后直接进入完整网站，一次验证解锁岗位筛选、岗位详情、岗位历史和趋势看板等全部功能。
- 3 天登录态内再次访问时直接进入完整网站，不重复询问邀请码。
- 邀请码错误时停留在输入页并显示失败提示；不显示岗位数据或业务页面资源。
- 邀请码明文由维护者自主设置，不要求系统替维护者生成固定格式。
- 明文只在受控终端输入和向受邀者发放时出现；不写入仓库、开放决策文档、发布记录、镜像、URL、浏览器日志或聊天记录。
- 运行配置只保存邀请码的不可逆哈希，并由 CVM root 所有、`0600` 权限保护；邀请码泄露时通过替换哈希整体撤销旧邀请码。
- 实现上采用独立邀请码入口、服务端校验、3 天安全 Cookie，以及 Web Edge 与 API 的双层门禁；这些是实现细节，不增加用户侧的额外步骤。
- 仅邀请码入口页和校验接口匿名可访问；完整业务 SPA、业务静态资源及所有业务 `/api/` 请求均需有效登录态。
- 现有浏览器原生 Basic Auth 不作为最终用户体验；不能把邀请码直接当作 Basic Auth 密码。

### 已落地的代码边界（2026-11-12）

- Go API 已增加匿名 `POST /api/v1/access/verify` 和内部会话检查 `GET /api/v1/access/check`。
- 业务 `/api/`、业务 SPA 和业务静态资源由 Web Edge 的 `auth_request` 保护；只有 `/access` 及其专用静态资源和验证接口匿名开放。
- 会话使用 3 天 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie；会话绑定当前邀请码哈希指纹，替换哈希即可整体撤销旧会话。
- Web Edge 已移除 Basic Auth；邀请码和会话签名材料只注入私有 API，不进入 Web Edge 镜像或前端产物。
- 证书资产已加入 root 受控的 Certbot 首次签发、webroot 续期、原子替换、失败回退和 systemd timer；尚未在 CVM 安装、签发或启用。
- 业务数据、账号、访问者身份、岗位正文和浏览行为不写入门禁会话或运维日志。

### 代码层收口验收（2026-11-12）

- `go test ./...` 已通过；本机 Go 构建缓存使用临时目录，不读取或改变运行时凭据。
- `web` 前端生产构建已通过，邀请码入口单元测试已通过。
- `make deploy-config-check` 已通过，包含 Web Edge、证书操作、发布生命周期、Compose 边界和公开预览检查。
- `openspec validate enable-invite-gated-public-preview --strict` 与 `git diff --check` 已通过。

## `www` 入口的取舍

不开放 `www` 的主要优点：

- 入口更少，DNS、证书、Host 校验和发布验收更简单。
- 只有一个规范地址，分享链接、Cookie 作用域和后续统计口径更统一。
- 减少一个需要长期维护的公网 Host，不会因为配置遗漏产生额外入口。

不开放 `www` 的主要缺点：

- 用户手动输入或误输入 `www.mrolescope.com` 时，不能自动跳转到正式入口；可能看到 DNS 解析失败或 TLS/Host 拒绝，而不是友好的重定向。
- 某些人习惯在域名前加 `www`，首次访问时可能产生“网站打不开”的误解。
- 如果未来外部资料、社交平台或第三方系统自动生成了 `www` 链接，需要额外修正链接或再补开入口。

本项目首轮以定向分享完整链接为主，因此接受上述缺点，暂不开放 `www`。该决定可逆：未来若发现用户误输入较多，可同时补充 `www` 的 DNS、受信任证书和 Host 配置，并将其永久重定向到规范入口；不需要改变业务 API 路径或邀请码逻辑。

## 当前不包含

- 不在本轮执行 DNS 修改、CVM 配置修改、安全组变更、证书签发或公网部署。
- 不把真实邀请码、TLS 私钥、云账号、支付信息、实名材料或数据库连接信息写入本文件。

## 公开 DNS 验证记录

### 2026-11-11

- 通过两个公共 DNS 解析器交叉查询，`mrolescope.com` 当前没有公开的 `A` 记录，也没有公开的 `AAAA` 记录。
- 当前公开 `NS` 记录为 `pineapple.dnspod.net` 和 `if.dnspod.net`，说明域名的权威 DNS 已委派到 DNSPod；这不等同于已确认维护者当前账号具有写入权限。
- 因为没有 `A/AAAA` 记录，当前无法通过域名访问 CVM，也尚未进入首次 ACME 验证阶段。
- 2026-11-11 维护者提供的腾讯云 DNSPod 控制台截图显示，`mrolescope.com` 已出现在当前账号的权威解析域名列表中；当前为免费版、记录数为 0，说明维护者具备进入该域名解析管理界面的权限。
- 截至该截图，仍未授权或执行 DNS 记录变更。后续应在发布前添加唯一的 `A` 记录指向 CVM；不添加 `www`、不添加 `AAAA`。
