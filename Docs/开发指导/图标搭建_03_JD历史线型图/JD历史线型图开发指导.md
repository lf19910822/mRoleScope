# 图表选择

尽可能复用已有的线型图设计。
用一条Y轴固定，X轴为日期的线型图表达JD修改历史，从左到右展示岗位变动历史。支持鼠标拖动，放大时间轴。
岗位变动在图中的展示阶段为：发现 - 修改 - 确认下线 - 重上线 - 最新。其中 确认下线 和 重上线 之间不应该再有横线，最新应当始终是当日，也就是最新一次同步成功的数据。
图表支持下钻，下钻展示面复用趋势看板 - 有改动岗位的上拉展示窗口，diff逻辑，git展现方式全部复用。

注意：图表中某个 修改 节点的下钻仅展示当前时间点前后的修改内容，并不是当前时间点和最新JD的区别。
比如：某JD在 11日修改过， 15日修改过，则11日的修改下钻仅展示11日前后的差别，15日仅展示15日前后差别。11日修改后和15日修改前，数据应该是一致的。

图表放在 岗位筛选 - 岗位详情页中，JD展示面的最下端。详情页岗位职责，任职要求，补充说明下面再加一项 岗位历史。

理论上目前的岗位筛选已经可以返回所有岗位了，只是无法精确还原某个时间点的岗位JD。加上这一套系统后应该就能实现。
