# 呈大计划守护者：岗位族建模开发进度与数据质量汇报（2026-10-29）

## 结论摘要

岗位族建模一期已经完成开发、生产部署、历史回填与日常增量接入。它以官方岗位分类和岗位标题为输入，通过版本化词典生成每个岗位唯一的主岗位族，并保留完整命中证据与重试审计；不读取 JD 正文、不调用 AI，也不向外部模型发送任何岗位内容。

截至 2026-10-29 17:27:14（Asia/Shanghai），最新已发布源站快照含 171 个唯一岗位：154 个（90.1%）已得到主岗位族，17 个（9.9%）为已完成但未命中字典的 `unclassified`。快照内观察、结果与已分类结果的证据覆盖均完整，且不存在待重试记录。该结果已经具备作为后续图表一期的“按日岗位族结构”事实来源的条件；图表 API、展示层和跨日差异口径尚未开发，仍待后续一期裁决。

## 二、已确定的关键决策


| 决策      | 采用规则                                                                   | 对数据产品的含义                       |
| ------- | ---------------------------------------------------------------------- | ------------------------------ |
| 解析范围    | 仅官方 `official_category.id = "1"` 的“程序&技术类”岗位进入正式岗位族解析。                 | 不将无关类别混入技术岗位族统计。               |
| 输入边界    | 只扫描规范化岗位标题；不读取 JD 正文、技术关键词、来源 `projectName`/`objectName`、地点、职级或 AI 输出。 | 规则可复现，且岗位族不依赖 AI 成本与稳定性。       |
| 项目词处理   | 仅掩蔽完整的审核项目片段，不掩蔽“引擎”“平台”“客户端”等通用岗位词。                                   | 避免项目名称污染，同时保留岗位标题的职业语义。        |
| 主岗位族唯一性 | 每个 JD 最多一个主岗位族：先比较岗位族命中次数；平局取标题中最后结束的有效命中；仍平局取 `family_key` 字典序最前。     | 主岗位族排行榜可按岗位去重计数，不会被多方向标题放大。    |
| 重叠别名    | 同一岗位族内部以最长别名去重；不同岗位族的命中均予保留。                                           | 既避免同族重复，又保留“服务端运维”等多方向标题的审计事实。 |
| 未分类     | `unclassified` 是有效完成结果，不能自动归入“其他”或任意现有岗位族。                             | 它量化的是当前词典覆盖缺口，而不是处理失败。         |
| 人工治理    | 不支持对单一标题手工覆写；仅能修改版本化词典或解析器后统一重算。                                       | 同标题始终得到同一结果，历史数据可追溯、可复算。       |
| 故障处置    | 保存可重试审计，继续处理其他岗位；下次 pending 流程自动补偿。                                    | 符合数据处理“最大努力交付”原则。              |


当前词典覆盖的 13 个主岗位族为：算法与研究、后端、游戏客户端、数据工程、研发管理与外包协作、游戏引擎、前端、硬件与嵌入式、运维、平台与 AI 基础设施、安全研发、测试、研发工具。

## 七、对图表一期的可用性与边界



### 已可作为图表事实来源的内容

- 可按已发布日快照计算岗位族总量、各主岗位族数量与占比。
- 可独立展示 `unclassified` 的数量和比例，避免将词典覆盖缺口隐藏在“其他”中。
- 可基于每日不可变快照建立日、周、月、季度、年度及自定义区间的主岗位族结构趋势；跨时间聚合时需由图表层明确采用“日快照”还是“可见期”作为分母。
- 可将多词典命中率与跨岗位族命中率作为数据质量/标题复合度指标，但不能与主岗位族排行榜直接相加或混算。
- 可显示词典及解析器版本，使词典版本升级后的历史重算具备解释依据。



### 本期尚未交付的内容

- 面向产品的图表查询 API、前端页面和交互。
- 专门的岗位族跨日新增、减少、迁移差异接口与展示语义。
- 对 `unclassified` 标题逐项的人工治理工作流；当前仅保留可审计事实，后续应通过版本化词典改进。
- 基于业务人工判断的岗位族“语义准确率”评价。当前报告不能以 90.1% 覆盖率替代语义正确率。



## 八、请大计划守护者裁决的后续方向

岗位族建模已完成首期数据基础，建议下一期图表设计时优先裁决以下事项：

1. **首个主视图。** 是否优先展示“最新日岗位族结构（数量、占比、未识别）”，再逐步扩展至趋势与差异。
2. **未识别展示策略。** 是否在所有结构图中把 `unclassified` 作为独立类别与比例显式展示，而非并入“其他”。
3. **时间分母。** 周、月、季度、年度及自定义区间应以“每日快照求和/均值”、区间末日快照，还是岗位可见期为默认口径；不同选择回答的是不同业务问题。
4. **规则变更展示。** 词典或解析器版本更新并重算后，图表是否需要标识规则版本切点，以区分真实岗位结构变化与规则覆盖变化。
5. **治理节奏。** 是否将 `unclassified` 比例、多词典命中率及跨岗位族命中率纳入常规数据质量看板，并以定期发布词典版本的方式治理，而非逐岗位人工覆盖。
