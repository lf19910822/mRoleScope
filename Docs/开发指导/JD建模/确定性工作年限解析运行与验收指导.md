# 确定性工作年限解析运行与验收指导

本指南定义 JD 正式工作年限字段的固定处理链。真实 JD、证据片段、数据库连接串和运行时密钥不得写入 Git、CI、普通日志或聊天。

## 正式来源与边界

- 正式工作年限结果只来自版本化的确定性工作年限解析器；它不构造模型客户端、不读取百炼 Key、不发起模型调用。
- AI 的年限结论、模型输出和审计记录仍是不可变历史资料，可供后续质量评估使用；正式读取在没有确定性结果时返回“不可用”，绝不回退到 AI 投影。
- `configured` 结果保存正整数 `base_year`，即所有无条件、必要的候选人经验下限中的最大值。必要的总体、领域和技术经验均可参与；`N-M 年`取 `N`。
- `not_configured` 表示没有通用必要下限，包括未提及、经验不限、仅优先项或仅学历条件分支；`uncertain` 表示识别到候选人年限但局部作用域无法确定。两者均是成功的非阻断处理结果，均不保存 `base_year=0`。
- `优先`、`优先考虑`、`者优先`、`加分`、`更佳`和`优聘`只在同一局部条款/原子内标记为 `preferred`，不能跨分号、句号或换行影响前文。`本科 3 年、硕士 2 年`等学历—年限分支标记为 `conditional`，不能产生通用 `base_year`。
- 每项保留年限表达均保存规则键、模态、最小年数、来源字段、字段规范化身份和 Unicode 码点区间；结果表不重复保存 JD 片段。

## 增量规则

结果身份固定为：`body_content_version_id + parser_version + lexicon_version + lexicon_sha256`。

1. 首次运行会处理所有尚没有当前身份结果的历史正文版本，形成一次性基线。
2. 同一身份的重复运行复用已有结果，不会重复创建记录。
3. 每日同步未产生新正文版本时，没有新的年限处理；JD 内容变化会产生新的 body version，并只处理该版本。
4. 解析器或词典版本（或词典 SHA-256）变化会形成新的身份，因而有意触发一次重新处理；旧结果和证据不被覆盖。

## CVM 受控操作

远端只使用既有 root-owned 固定入口：

```bash
sudo /usr/local/sbin/mrolescope-analysis pending
```

该入口启动固定 worker 子命令 `analyze`，不接受正文、body ID、词典内容、模型、数据库 URL 或自由参数。它依次独立运行确定性项目、学历和工作年限处理，再独立尝试已发布的技术词典分析；任一链路的故障不会阻止其他链路被尝试。常规输出只含 `experience_processed`、`experience_reused`、按状态计数及其他安全聚合。

成功的数据同步会 best-effort 启动同一分析服务。分析失败不会回滚已成功的来源同步、COS 归档或岗位可见期；下一次固定分析会继续处理仍缺少当前身份结果的版本。

部署完成后，由运维人员人工运行一次上述 `pending` 操作建立年限基线。随后无需增加 timer：既有每日同步的下游 best-effort 分析会自然处理后续新增或变化正文。不得用 AI 试跑、扩展或发布操作来建立年限基线。

## 无正文验收

验收只检查聚合计数和状态：

1. 首次 `pending` 后，当前解析器/词典身份的年限结果数应覆盖已有正文版本数。
2. 紧接着第二次 `pending`，年限新增处理数应为零，重用或无待处理均属预期。
3. 引入一个新 body version 后再次运行，只应新增该版本的一条当前身份结果。
4. 允许检查状态、`base_year`、版本标签、词典 SHA-256、字段名、规则键、模态、码点区间和安全错误类别；禁止输出 JD 正文、证据片段、模型输入/输出、API Key 或数据库 URL。

技术提及的候选、发布与回退流程仍遵循[JD 技术提及：远端运行与验收指导](JD技术提及远端运行与验收指导.md)。本指南不改变人工发布的技术词典或 AI 配置流程。
