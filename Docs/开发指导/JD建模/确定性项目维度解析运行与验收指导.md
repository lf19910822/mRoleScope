# 确定性项目维度解析运行与验收指导

本指南定义 JD 正式项目维度的固定处理链。真实 JD 标题、证据片段、数据库连接串和运行时密钥不得写入 Git、CI、普通日志或聊天。

## 正式来源与边界

- 正式项目结果只来自人工审核、版本化的项目词典与规范化岗位 `title` 的确定性匹配；不构造模型客户端、不读取百炼 Key、不发起模型调用。
- 词典条目只有两种展示分类：`named_game`（明确游戏）与 `source_direction`（来源方向或预研标签）。方向标签不得被展示或统计为已确认游戏。
- 来源接口的 `projectId`/`projectName`、JD 正文提及、技术关键词、技术 AI 结果和历史模型输出均不是正式项目归属来源，也没有回退资格。
- 标题无命中会保存为已完成的空结果，产品展示为“未识别”；它不等于公共平台、无项目或同步遗漏。
- 每个标题匹配保留项目稳定键、展示名称快照、分类、词典版本/摘要、命中关键词和 Unicode 码点区间。原始标题继续由受控来源元数据保存，普通日志不输出它。

## 初始词典与增量规则

首版词典包含[项目维度开发](项目维度开发.md)审核的 15 个条目：10 个明确游戏和 5 个来源方向/预研标签。仅登记的精确关键词可匹配：英文关键词按明确的 ASCII 标识符边界大小写不敏感匹配；中文词面、空格、标点、缩写、译名和别名不会自动扩展。

结果身份固定为：`title_identity + parser_version + dictionary_version + dictionary_sha256`。

1. 首次运行会为已有的规范化标题建立一次性基线，包括未识别标题。
2. 同一身份的重复运行复用已有结果，不会重复创建项目标签或证据。
3. 每日同步只有发现新标题时才新增处理；地点、工作性质和其他非标题来源元数据变化只建立来源观察关联并复用已有标题结果。
4. 标题变化生成新的标题身份；解析器、词典版本或词典 SHA-256 变化有意对已知标题重新处理，旧结果保持不可变。
5. 同一标题命中多个不同条目时全部保留；未来存在包含关系的词典项以更长匹配优先，绝不以扫描顺序覆盖。

维护者新增名称、别名或归属关系时，必须先人工核验，再更新为新的词典版本。不得自动采纳未知标题后缀、正文提及或模型建议。只是更改展示名保持稳定键；合并或拆分条目须另行定义历史映射口径。

## CVM 受控操作

远端只使用既有 root-owned 固定入口：

```bash
sudo /usr/local/sbin/mrolescope-analysis pending
```

该入口启动固定 worker 子命令 `analyze`：它先独立处理确定性项目标签和学历结果，再尝试已发布的技术词典分析。常规输出仅包含 `project_processed`、`project_reused`、`project_unidentified`、学历与技术链路的聚合计数，不含标题、JD 正文、词典内容或模型数据。

首次部署后由运维人员人工执行一次 `pending` 建立基线。此后既有每日同步的下游 best-effort 分析会处理新标题，无需增设 timer。项目基线不得通过 `analyze-ai`、AI 试跑、扩展或发布操作建立。

## 无正文验收

1. 首次 `pending` 后，当前解析器/词典身份的项目结果数应覆盖已有不同标题身份数；其中可以存在零分配的未识别结果。
2. 紧接着第二次 `pending`，项目新增处理数应为零。
3. 仅改变地点等来源元数据后再次运行，不应增加项目结果；同标题的新来源元数据版本仍应能读取既有项目结果。
4. 引入一个新标题后再次运行，只应新增该标题的一条当前身份结果；词典版本更新则是预期的历史标题重新处理。
5. 验收允许检查聚合计数、状态、版本、摘要、项目稳定键、分类、命中关键词和码点区间；禁止输出 JD 标题、正文、模型输入/输出、API Key 或数据库 URL。
