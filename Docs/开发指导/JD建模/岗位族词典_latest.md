# 岗位族词典（最新正式版）

版本：`deterministic-job-family-dictionary-v3`  
生效资产：`internal/jdanalysis/job_family_dictionary_v3.json`  
更新日期：2026-10-30  
状态：**已裁决，待随本次实现合并与部署。**

本文是岗位标题词典的人工维护入口和可读版本。运行时以同版本 JSON
资产为准；V1、V2 资产和据其生成的历史结果均不可修改、不可删除。任何
新词、改归属或禁用词均须经新的审核与版本发布，不能为单个标题写覆盖值。

## 1. 使用边界

- 输入仅为规范化岗位标题及已审核项目词典的精确屏蔽范围；不读取 JD
  正文、项目元数据、技术词结果或 AI 输出。
- 仅命中下文列出的连续字面别名；不做正则、分词、模糊匹配、同义词扩展或
  自动词形变化。
- 标注“ASCII 不分大小写、标识符边界”的别名仅在 ASCII 大小写不同的情况
  下等价，且前后不能紧邻英文字母、数字或下划线。例如 `AI` 不会匹配
  `AIOps` 的前缀。
- 一条完整别名只能属于一个岗位族；不同岗位族可分别命中重叠片段。同族
  内重叠别名只保留最长的一条。
- 每个族的有效非重叠命中各计一次。唯一主岗位族依次取：命中次数最多、
  最后有效命中结束位置更靠后、`family_key` 字典序更小。多岗位族命中不是
  错误，也不会产生第二个主岗位族。

## 3. V2 到 V3 的迁移

下列完整别名在 V3 仅变更唯一所有者；通用 `算法`、`搜推`、`后端`、`全栈`、
`AI`、`agent` 等仍在既有岗位族，故可和新族并行命中。

| 原 V2 所有者 | V3 所有者 | 迁移别名 |
| --- | --- | --- |
| `algorithm_research` | `ai_algorithm` | `模型研究`、`预训练`、`后训练`、`模型评测`、`Posttrain`、`搜推AI` |
| `backend` | `ai_application` | `AI 应用`、`Agent 开发`、`Agent开发`、`Agent研发` |

`AI应用` 与 `Agent 研发` 是同一已裁决概念的空格变体，作为 V3 的完整新别名
登记；它们不在 V2 中重复占有。`LLM Post-train 算法`、`LLM Posttrain 算法`
是已裁决“带空格和不带空格的中英混合写法都列出”的空格变体，用于覆盖现有
标题的实际拼写；不引入新的语义类别。

## 4. 明确不交给新增 AI 岗位族的裸词

`AI`、`LLM`、`大模型`、`Agent`、`AIGC`、`RAG`、`MCP`、`Prompt`、`工作流`
不能单独产生 `ai_algorithm` 或 `ai_application`。其中 `AI`、`agent`、`大模型`
仍按上方 `platform_infra` 的既有宽信号匹配；这不等于它们属于新增 AI 岗位族。
`LLM`、`AIGC`、`RAG`、`MCP`、`Prompt`、`工作流`未作为任何单独 V3 别名启用。

例如，`大模型平台开发工程师`仍是平台与 AI 基础设施，`AI Agent引擎系统开发
工程师`也不会仅因 AI/Agent 被归为 AI 应用；`云游戏技术专家`仍是
`unclassified`。只有发布后经审核的下一版词典，才可改变这些边界。
