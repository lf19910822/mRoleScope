# 确定性学历解析运行与验收指导

本指南定义 JD 正式学历字段的固定处理链。真实 JD、证据片段、数据库连接串和运行时密钥不得写入 Git、CI、普通日志或聊天。

## 正式来源与边界

- 正式学历结果只来自版本化的确定性学历解析器；它不构造模型客户端、不读取百炼 Key、不发起模型调用。
- AI 的学历结论、模型输出和审计记录仍是不可变历史资料，可供后续质量评估使用；正式读取在没有确定性结果时返回“不可用”，绝不回退到 AI 投影。
- 词典把候选人的学历词面映射到 `associate_or_lower`、`bachelor`、`master`、`doctor`；其中 `研究生` 按产品约定映射为 `master`，`博士研究生` 优先映射为 `doctor`。
- 结果保存 `configured`、`not_configured` 或 `uncertain`，并分别保存学历下限和上限。`本科及以下` 是上限，不是最低本科；优先/加分项不能建立硬性下限。

## 增量规则

结果身份固定为：`body_content_version_id + parser_version + lexicon_version + lexicon_sha256`。

1. 首次运行会处理所有尚没有当前身份结果的历史正文版本，形成一次性基线。
2. 同一身份的重复运行复用已有结果，不会重复创建记录。
3. 每日同步未产生新正文版本时，没有新的学历处理；JD 内容变化会产生新的 body version，并只处理该版本。
4. 解析器或词典版本（或词典 SHA-256）变化会形成新的身份，因而有意触发一次重新处理；旧结果和证据不被覆盖。

## CVM 受控操作

远端只使用既有 root-owned 固定入口：

```bash
sudo /usr/local/sbin/mrolescope-analysis pending
```

该入口启动固定 worker 子命令 `analyze`，不接受正文、body ID、词典内容、模型、数据库 URL 或自由参数。它会先运行确定性学历处理，再独立尝试已发布的技术词典分析；任一链路的故障不会阻止另一链路被尝试。常规输出只含 `education_processed`、`education_reused` 和技术分析计数。

成功的数据同步会 best-effort 启动同一分析服务。分析失败不会回滚已成功的来源同步、COS 归档或岗位可见期；下一次固定分析会继续处理仍缺少当前身份结果的版本。

部署完成后，由运维人员人工运行一次上述 `pending` 操作建立学历基线。随后无需增加 timer：既有每日同步的下游 best-effort 分析会自然处理后续新增或变化正文。不得用 `analyze-ai`、AI 试跑、扩展或发布操作来建立学历基线。

## 无正文验收

验收只检查聚合计数和状态：

1. 首次 `pending` 后，当前解析器/词典身份的学历结果数应覆盖已有正文版本数。
2. 紧接着第二次 `pending`，学历新增处理数应为零，重用或无待处理均属预期。
3. 引入一个新 body version 后再次运行，只应新增该版本的一条当前身份结果。
4. 允许检查状态、版本标签、词典 SHA-256、字段名、规则键、码点区间和安全错误类别；禁止输出 JD 正文、证据片段、模型输入/输出、API Key 或数据库 URL。

技术提及的候选、发布与回退流程仍遵循[JD 技术提及：远端运行与验收指导](JD技术提及远端运行与验收指导.md)。本指南不改变人工发布的技术词典或 AI 配置流程。
