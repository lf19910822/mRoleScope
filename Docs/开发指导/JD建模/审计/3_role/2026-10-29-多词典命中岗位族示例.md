# 2026-10-29 多词典命中岗位族示例（最新快照）

## 审计结论

最新已发布快照（2026-10-29，171 个岗位）中，已分类岗位为 154 个。此前汇报中的 **37 个“多命中”**，经本次逐岗位只读复核，准确含义是：岗位标题的确定性解析结果中，满足以下任一条件的岗位共有 37 个（占已分类岗位 24.0%）：

1. 命中 **多个不同岗位族**；或
2. 只命中一个岗位族，但该岗位族的有效词典命中次数大于 1。

因此，37 并不等同于“37 份 JD 均命中多个岗位族”。其中：

| 多命中类型 | 岗位数 | 说明 |
| --- | ---: | --- |
| 跨岗位族命中 | 14 | 命中两个不同岗位族，且各岗位族的有效命中次数均为 1。 |
| 跨岗位族命中，且其中一族重复命中 | 4 | 命中两个不同岗位族，其中一个岗位族有多个有效词典命中。 |
| 同岗位族内重复命中 | 19 | 只归入一个岗位族，但该岗位族有多个有效词典命中。 |
| 合计 | 37 | 上述三类互斥，按最新快照的唯一岗位计数。 |

所以，真正的“多岗位族”岗位共有 **18** 个（14 + 4）；37 是更宽的“多词典命中”口径。下面完整列出 37 个岗位，以便人工检查词典边界与主岗位族选择。

## 口径说明

- **岗位名称**：最新快照对应的规范化岗位标题；未读取或记录 JD 正文。
- **主岗位族**：正式产出的唯一 `primary_family_key`；每份 JD 仍只计入一个主岗位族。
- **全部命中岗位族（有效次数）**：`岗位族（match_count）`。次数是该岗位族保留下来的有效词典命中数，不是岗位数量，也不是人工判断的业务相关性强弱。
- 同一岗位族的重叠别名已按“最长别名优先”消重；不同岗位族的命中会同时保留。主岗位族按“命中次数 → 标题中最后结束的有效命中 → `family_key` 字典序”决定。
- 本清单是规则审计材料，不对词典命中是否符合业务语义作裁决。

岗位族中文名称映射：`algorithm_research` = 算法与研究，`backend` = 后端，`client` = 游戏客户端，`data_engineering` = 数据工程，`engineering_management` = 研发管理与外包协作，`engine_systems` = 游戏引擎，`operations_sre` = 运维，`platform_infra` = 平台与 AI 基础设施，`security` = 安全研发，`testing_quality` = 测试，`toolchain` = 研发工具。
