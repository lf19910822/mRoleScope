## 第 1 轮已经裁定、在本轮直接适用的口径

下列规则来自 [审计/1](../1/README.md) 及其已批注样本，不在本轮重复征求裁决：

1. `base_year` 有明确总体证据时可独立保存；无法表达 `A/B/或` 的领域关系时，首期仅保留总体年限，领域项降级或省略。
2. 候选词只收集候选人资格要求中的陌生技术代名词/缩写，最多 3 个；职责、产品/行业、工作流、通用能力、物理对象、流程和泛化概念不收集。
3. 候选词或个别模型字段有问题，不能阻断已独立验证的学历、总体年限和其他可用结论。
4. 分别陈述的硬性技术要求不能自动合并成“任选其一”；`优先` 不得写成 `required`。
5. 熟练度按受控提示词的明确映射处理：`了解=P1`、`熟悉=P2`、`熟练/熟练掌握/能独立使用=P3`、`精通/专家级/深入掌握=P4`；未明确则 `null`。

## 通用提示词契约（V3）

以下片段是五份样本共同的判定依据：

> 技术选项还必须引用对应的 `mention_evidence_id`；ID 不存在、不能支持结论或关系不明确时，使用 `uncertain` 和 `required_review`，绝不编造证据、技术 ID 或片段。

> 只有 `role=qualification` 参与候选人要求组；`responsibility` 是入职后工作内容。

> `优先`、`加分`、`更佳` 等明确可选条件为 `preferred`；不同片段中分别陈述的正向 `required` 资格绝不可合并成任选。

> `requirement_groups` 的 options 只能使用 `verified_technology_mentions` 中已有的 `technology_key`。

> 词典外候选只收集候选人资格中的陌生术语；职责、加分项以外的普通提及、产品/行业/领域、工作流、通用能力、物理对象、流程和泛化概念不得输出为候选。
