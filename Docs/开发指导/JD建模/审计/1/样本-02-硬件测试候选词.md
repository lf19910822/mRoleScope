# 样本 02：硬件测试术语被大量列为候选词

## 1. 问题简介与失败环节

本正文版本同样有 P1、P2、P3 三个失败任务。P1/P2 的账本均为 `policy_rejected`，旧执行路径未记录首个细分阶段；因此不能把“候选词持久化”写成它们的运行时既定事实。P3 的 799 Token 完整 JSON 通过了结构与引用层，在**候选技术词持久化**（`candidate_mention`）阶段被历史路径拒绝。

P3 所依赖的技术词典状态是 `published`。模型输出了 9 个候选词，旧路径试图将其写进该冻结词典的候选治理队列，导致整份 JD 以 `policy_rejected` 结束。对同一保存回复的离线、必定回滚重放，在把冻结词典候选转为 `uncertain/required_review` 审计事实后已可完成。这说明“候选词是否应保留”和“候选词问题是否应阻断学历、年限等独立结论”是两个需要分开裁决的问题。

## 2. JD 相关证据片段

> `[jobRequire:s01]` 1、本科及以上

> `[jobRequire:s03]` 2、3 年以上消费电子 / 智能硬件测试经验

> `[jobRequire:s05]` 4、具备独立复杂问题分析能力：能使用示波器、负载、电源、温箱、噪音仪等定位硬件 / 底层问题

## 3. 模型得出的结论

以下是各次保存 JSON 的字段转写；候选词的角色和必要性在三次中均由模型给为 `qualification/required`，并且均标为 `required_review`。


| 回复  | 经验与学历                                                                                                                     | 词典外候选词                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| P1  | `base_year=3`，仅领域项 `consumer_electronics ≥ 3`；学历 `bachelor`。                                                              | 示波器、负载、电源、温箱、噪音仪、电路、电机驱动、屏 / 触控原理、测试脚本、DFMEA、测试风险评估、量产准入流程。 |

P1 的领域键 `consumer_electronics` 并非原文片段逐字复制；P2 则未给出承载 `base_year` 的 item。P3 已使用原文领域并补出总体 item，但它的候选列表仍混合了仪器、部件/概念和测试能力/脚本。上述只描述模型输出，未给出“哪些算技术”的裁决。

## 4. 提示词相关片段

> V2/V3：`scope_type=domain` 时，`scope_key` 必须逐字复制自且只出现于一个引用 `evidence_span_ids` 的原文片段。

> V3：`configured` 时同时给出 `items`（至少输出一项），总体年限使用 `scope_type=base`、`scope_key=overall`。

> 三版技术关系规则：词典外技术放 `candidate_mentions`，绝不伪造 `technology_key` 或让候选词成为有效 options。

> 三版复核规则：词典外候选必须是 `required_review`。

提示词没有给出“候选技术词”的最小粒度或排除类型，例如仪器、硬件部件、方法论、流程名、通用能力和技术名之间的边界。它也没有授权模型把候选词写成有效技术要求；P3 未生成技术组，符合这一限制。
