# JD 建模人工审计索引

> 访问级别：仅限项目授权审计。本文档按授权摘录最小必要的 JD 片段与模型结论，供 FAN 批注；不得将其复制到日志、工单、聊天、CI 或公开材料。

## 用途与裁决原则

这里记录的是**已经失败且仍保留模型回复**的 JD 建模任务。每一份样本文件都严格分成四类信息：运行事实、JD 证据片段、模型结论、提示词规则；最后只提出待 FAN 裁决的问题，不把模型结论直接当成事实，也不替 FAN 预先决定提示词或工作流应如何改。

文中的“合理”“不合理”只能由 FAN 在阅读同一份证据后批注。程序运行时的 `policy_rejected`、`invalid_response_schema` 等是失败位置，不是对候选人要求真伪的判断。

## 共同的工作流事实

P3 的 4 条 `policy_rejected` 均已在离线、必定回滚的诊断中被定位为 `candidate_mention` 持久化环节。它们依赖的技术词典状态为 `published`。保存回复的离线重放在采用“冻结词典中的候选词作为 `uncertain` 审计事实，而非尝试写入词典候选队列”的路径后，4 条均可完成；该重放不调用模型也不改写历史失败账本。

这证明的是持久化边界存在断层，并不证明模型列出的候选词都应该被保留。各文件故意把“候选词本身是否合理”和“局部候选词问题能否让整份 JD 失败”拆开，请分别裁决。

## 证据表示约定

- `P1`、`P2`、`P3` 是同一正文版本的三次模型回复，不是三个不同 JD。
- 方括号内的 `jobRequire:sNN`、`description:sNN`、`addition:sNN` 是当次模型可见、程序生成的片段引用；文中随后给出其最小原文片段。
- “模型结论”是对已保存 JSON 的逐字段转写或压缩，不是人工修正后的答案。
- 某个旧任务只记录了 `policy_rejected` 而未保留阶段名称时，文件会明确写“阶段未记录”；不会把代码阅读所得的可能路径伪装成运行时事实。
