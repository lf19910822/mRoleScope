# 百炼开通与密钥配置操作指引

> 适用范围：`implement-ai-jd-semantic-analysis` 的受控试跑。本文只指导账户侧开通、计费确认和密钥创建；不要求把密钥发给任何人，也不在本地、Git、GitHub Actions 或聊天中保存密钥。
>
> 核验日期：2026-10-25。链接均为阿里云官方一手文档或官方控制台。模型价格、端点和控制台界面会变动，实际试跑前仍须按第 4 步重新核对。

## 先知道三件事

1. 不需要购买一串可下载的“AI Token”。百炼的千问 API 是按调用量自动计费；官方说明是确认账户未欠费即可调用，消费明细按分钟级出账。请先确保付款方式、余额或信用额度能覆盖调用，而不是购买或填写第三方的 Token。[官方说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen#5bfff3e5c0tgy)
2. 本项目的第一步不是全量分析，而是固定的 5 份 JD × Plus/Flash 两个模型的受控试跑。程序限制为 10 个逻辑任务、最多 30 次物理尝试，且共享预算上限为 **2.50 元**；实际请求还受每次最多 10,000 输入 Token、5,000 输出 Token 限制。即使阿里云侧的预算告警还没生效，这个项目内的前置预算门也会阻止超出该上限的请求。
3. 创建 Key 和把 Key 配入 CVM 是两件事。现在可以完成前者；只有 AI 代码已通过 CI、合并、受控部署，且我方只读验收确认 AI 单元已就绪后，才执行本文第 7 步。不要为了测试在本机或 CVM 手工发送任意 API 请求；固定 worker 只使用由北京 WorkspaceId 推导的专属端点。

## 0. 开始前的条件

- 使用能够签署服务协议、处理计费和管理 API Key 的**阿里云主账号**。阿里云的首次调用指南明确要求使用主账号开通百炼。
- 若开通页提示未实名认证，先按阿里云账户提示完成实名认证；这是百炼开通的前提。[开通与实名认证说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen#f92b9b9cc7huw)
- 不要创建阿里云 RAM `AccessKey ID/AccessKey Secret` 来代替本文所需的百炼 API Key；它们不是同一种凭据。
- 准备一个受自己控制的密码管理器条目，用于临时保存新建 Key。不要保存到项目 `.env`、笔记截图、终端历史或聊天。

## 1. 开通阿里云百炼

1. 登录阿里云主账号后，打开官方百炼模型市场：<https://bailian.console.aliyun.com/model/market>。如果控制台出现地域选择，选择“华北 2（北京）”。
2. 首次进入时，阅读服务协议并选择同意/开通。官方说明：同意后自动开通；若没有弹出协议，通常表示该账号已经开通。[首次调用千问 API：账号设置](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen#f92b9b9cc7huw)
3. 不要在此阶段创建应用、Agent、知识库、模型微调任务，也不要把真实 JD 粘贴到“体验中心”。本项目仅需 API 调用 `qwen-plus` 与 `qwen-flash`。

完成标志：能进入百炼控制台且没有“请开通服务”阻挡页面。

## 2. 选择并记录北京业务空间

虽然 CVM 位于上海，但百炼模型服务的部署地域独立于调用方地域。阿里云当前官方地域列表中没有“上海”百炼地域；中国大陆列出的可用地域是**华北 2（北京）**。因此，本项目只能采用“上海 CVM 调用北京百炼业务空间”的组合，不能创建不存在的上海百炼 Workspace 或上海 API Key。若业务存在必须不离开上海地域的硬性数据驻留要求，应在创建 Key 前停止本接入方案，另行选择具备上海模型推理地域的供应商。

项目的价格档案和合规边界都以**华北 2（北京）**为目标地域。进入官方业务空间页：<https://bailian.console.aliyun.com/cn-beijing/settings/workspace>。

1. 在控制台地域选择中确认是“华北 2（北京）”。
2. 查看默认业务空间；如果控制台要求先创建业务空间，按页面向导创建一个仅供 `mRoleScope` 使用的业务空间，例如 `mrolescope-production-trial`。不要在业务空间名、描述或标签中放 JD 正文、用户信息或密钥。
3. 记录**业务空间 ID（WorkspaceId）**，但不要把它当作密钥。它可以用于定位区域端点，仍应只放在受控运行配置中，而非 GitHub Actions 输入。

官方文档说明，地域、API Key 与模型列表相互独立，不能跨地域混用；北京调用需要在 Base URL 中包含 `WorkspaceId`，其值可在上述“业务空间管理”页查看。[地域与端点官方说明](https://www.alibabacloud.com/help/zh/model-studio/regions)

### 与当前项目代码的关系（必须确认）

阿里云目前推荐北京地域使用专属端点：

```text
https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

官方说明旧的 `https://dashscope.aliyuncs.com` 域名仍可用于既有调用，但已在 **2026-09-30** 后不再支持新特性，并建议生产调用迁移到业务空间专属域名。地域、API Key 和模型列表彼此独立，不能跨地域混用。[地域与端点官方说明](https://www.alibabacloud.com/help/zh/model-studio/regions)；[OpenAI 兼容 Chat API：迁移说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

本修订将项目迁移为只接受受控的北京 `WorkspaceId` 并构造专属端点；该端点也被纳入不可变请求档案，变更业务空间会生成不同的候选配置。只有在本修订通过 CI、合并并受控部署后，CVM 才会获得这一行为。由于本项目依赖严格 JSON Schema 等受控能力，旧域名“未来新特性不支持”的官方限制不应被当作可接受的生产前提。因此：

- 可以继续完成账户开通、费用确认、北京业务空间记录和 API Key 创建；
- **不要**把 Key 写入 CVM、也不要启动真实试跑；
- 对应端点迁移修订必须完成审查、CI、合并、受控部署与无正文验收后，才允许写入 CVM 运行时配置；
- 绝不能通过临时改 Compose、环境变量或手工进入容器修改端点来绕过流程。

## 3. 确认计费能力，而非购买 Token

1. 打开阿里云“费用与成本”中心：<https://usercenter2.aliyun.com/home>。
2. 查看账户是否欠费，以及付款方式、账户余额或授信状态是否可用于按量付费。若页面提示充值、绑定付款方式或补缴欠费，按控制台的官方提示完成；充值入口为 <https://usercenter2.aliyun.com/finance/fund-management/recharge>。本项目不要求购买某个模型的固定 Token 包。
3. 之后可在官方账单详情查看消费：<https://billing-cost.console.aliyun.com/finance/expense-report/expense-detail-by-instance>。百炼官方说明千问调用会自动扣费、账单为分钟级；不要用“账单尚未出现”判断调用一定未发生。[计费与账单说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen#35e900bd4bf9r)

建议只为试跑预留小额、可接受的按量付费余量。项目自身还有 2.00 元的硬性试跑预算门，但账户侧余额不足会导致请求失败，不能代替该门禁。百炼 API Key 有不同计费类型；本项目需要的是按量付费 API Key（前缀为 `sk-`），而不是 Token Plan（`sk-sp-`）或 Coding Plan（`sk-ws-`）。[API Key 类型官方说明](https://www.alibabacloud.com/help/zh/model-studio/get-api-key)

## 4. 重新核对目标模型、地域和价格

在创建 Key 后、首次真实试跑前，依次打开以下官方模型页，在“华北 2（北京）”栏确认模型仍可用、仍支持结构化输出，并记录页面显示的当前价格：

| 试跑角色 | 固定模型 ID | 官方页 | 2026-10-25 核验的短上下文价格（元/百万 Token） |
| --- | --- | --- | --- |
| 首版候选基线 | `qwen-plus` | [qwen-plus](https://help.aliyun.com/zh/model-studio/qwen-plus) | 输入 0.8；输出 2 |
| 仅作成本/质量对照 | `qwen-flash` | [qwen-flash](https://help.aliyun.com/zh/model-studio/qwen-flash) | 输入 0.15；输出 1.5 |

两页均列出华北 2（北京）可用性和“结构化输出”支持；`qwen-plus` 页面列出的短上下文阈值是输入不超过 128K，`qwen-flash` 则按输入长度阶梯计费。项目一次请求上限远低于该阈值（10K 输入、2.5K 输出）。

价格或模型能力若与上表不一致：**停止在第 6 步之前**，不要启动试跑。项目的冻结定价档案、预算门和测试需要先按新官方价格更新、审查、CI、合并、部署，才可使用新价格调用。

## 5. 设置账户侧消费预警（建议，但不是硬停止）

阿里云提供“预算管理”，可按账户、产品、地域等范围建立费用预算，在实际或预测消费达到阈值时以邮件、短信或站内信提醒。[预算管理官方文档](https://help.aliyun.com/zh/user-center/how-to-manage-a-budget)

操作路径：

1. 打开“费用与成本”中心：<https://usercenter2.aliyun.com/home>。
2. 左侧进入“预算管理”；首次使用点击“免费开通”。
3. 选择“创建预算” → “费用预算”。
4. 预算名称可填写 `mRoleScope 百炼试跑`；预算范围优先筛选本账号、产品“大模型服务平台百炼”（若控制台提供该产品筛选）和北京地域；周期选月。
5. 为试跑设置一个自己可接受的月度金额，例如 10 元；可添加 50%、80%、100% 三档预警，并确认接收邮箱/手机号已经验证。

必须理解其限制：官方明确说明预算告警只通知，**不会限制资源继续使用**；费用预算的数据与预警具有 T+1/T+2 延迟。因此它是账户侧提醒，不是本项目运行前的成本闸门。本项目 2.00 元的请求前预留预算才是试跑的即时停止机制。

## 6. 创建最小权限的百炼 API Key

> **按量 Key 前缀（2026-10-25 核验）**：百炼已升级按量付费 API Key 的生成和存储机制（美国弗吉尼亚地域除外）。升级前创建的按量 Key 以 `sk-` 开头，仍可使用；升级后在“按量付费”入口新建的 Key 以 `sk-ws` 开头，功能相同，完整明文仅在创建时显示一次。不要仅凭 `sk-ws` 前缀把这类新 Key 误判为 Coding Plan；应以创建入口“按量付费”、所属地域和业务空间专属 Base URL 为准。该更新见阿里云官方英文文档的 [API key security upgrade](https://help.aliyun.com/en/model-studio/get-api-key#api-key-security-upgrade)。

1. 打开北京地域的官方 API Key 页：<https://modelstudio.console.alibabacloud.com/cn-beijing/model/settings/api-key>。若该页面要求重新登录，完成登录后确认页面右上角仍为“华北 2（北京）”。也可从百炼控制台的 [API Key](https://bailian.console.aliyun.com/model/settings/api-key) 页面进入。
2. 点击“创建 API Key”。本项目只使用“按量付费”入口；不进入 TokenPlan 或 CLI/Coding Plan 页面。新建 Key 的前缀可能是 `sk-ws`，这是当前按量付费 Key 的安全升级格式，不需要为取得旧 `sk-` 前缀而重建。
3. 名称可填写 `mrolescope-ai-trial-20261025`（名称只作审计识别，不要含正文、人员简历或密钥）。
4. 若表单包含“归属业务空间”，选择第 2 步确认的北京业务空间。权限选择“自定义”，开启“访问模型范围”，只勾选：
   - `qwen-plus`
   - `qwen-flash`
5. 如需 IP 白名单，只有在已经确认 CVM 出口 IP 固定、且白名单内容由你本人核对时才填写；未确认前不要猜测地址，以免阻断受控试跑。后续可以在不改 Key 值的情况下收紧。
6. 提交创建，按控制台提示立即保存到自己的密码管理器，随后关闭展示页面。不要依赖“以后一定还能查看完整 Key”；如无法安全确认，删除并新建，而不是在聊天或文件中备份。

若 Key 已创建但未启用模型白名单：在其操作菜单选择“编辑”，切换为“自定义”，开启“访问模型范围”，仅保留 `qwen-plus`、`qwen-flash`。若完整 Key 未在创建时保存，则编辑无法找回明文；删除该未保存的 Key 后按上述限制重新创建即可。

官方说明：创建 Key 时无需先选择模型；可通过自定义权限的“访问模型范围”限制该 Key 仅能调用所选模型。这正适合本项目的 Plus/Flash 固定试跑。[官方 API Key 创建与最小模型范围说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen#f92b9b9cc7huw)；[API Key 权限、地域和业务空间的官方说明](https://www.alibabacloud.com/help/zh/model-studio/get-api-key)

不要做以下事情：

- 不要把 Key 发给我或其他助手；
- 不要把 Key 写入仓库 `.env`、源码、Docker 镜像、Compose 文件、GitHub Secret、GitHub Actions 输入框、工单、终端截图或普通日志；
- 不要为方便排障赋予“全部模型”权限；
- 不要用 Key 做控制台“随手测试”，因为这会把任意输入送出且绕开项目审计/预算门。

## 7. 受控部署完成后：由你本人写入 CVM 密钥文件

仅在以下条件同时满足后执行：第 2 节所述北京专属端点迁移已完成，且对应修订已合并到 `main`、CI 通过、受控部署完成、AI 单元/迁移已只读验收通过。

登录 CVM 后，先检查密钥文件权限；这不会显示内容：

```bash
sudo -n stat -c 'secret_file=%U:%G:%a' /etc/mrolescope/secrets/remote-development.env
```

期望输出为：

```text
secret_file=root:root:600
```

然后由你本人执行：

```bash
sudoedit /etc/mrolescope/secrets/remote-development.env
```

在**保留现有所有行**（尤其是 `DATABASE_URL`）的前提下，在文件末尾加入两行。`WorkspaceId` 不是密钥，但也不应贴入聊天或 GitHub Actions 输入：

```dotenv
MROLESCOPE_QWEN_WORKSPACE_ID=此处仅由你填写北京业务空间 ID
MROLESCOPE_QWEN_API_KEY=此处仅由你粘贴新建的百炼 API Key
```

保存退出。不要把编辑器内容复制回聊天，也不要使用 `cat`、`echo`、`printenv`、`docker inspect` 或 shell history 来检查 Key。只执行下面的无值验证：

```bash
sudo -n bash -c 'f=/etc/mrolescope/secrets/remote-development.env; test -f "$f"; stat -c "secret_file=%U:%G:%a" "$f"; awk -F= '\''$1=="MROLESCOPE_QWEN_WORKSPACE_ID" { print "qwen_workspace=" (length($2)>0 ? "present" : "empty"); workspace=1 } $1=="MROLESCOPE_QWEN_API_KEY" { print "qwen_key=" (length($2)>0 ? "present" : "empty"); key=1 } END { if (!workspace) print "qwen_workspace=missing"; if (!key) print "qwen_key=missing" }'\'' "$f"'
```

期望仅包含：

```text
secret_file=root:root:600
qwen_workspace=present
qwen_key=present
```

出现 `missing` 或 `empty` 时停止，不运行试跑；重新用 `sudoedit` 修正。出现其他权限时停止，先恢复为 `root:root:600`，不以放宽权限的方式继续。

## 8. Key 就绪后的受控流程

完成第 7 步不代表立刻全量外呼。后续只能按项目的固定 GitHub Actions 操作顺序执行：

1. `prepare-ai-trial` / `PREPARE_AI_TRIAL`：只创建固定 5×2 试跑任务，不发送正文；
2. `run-ai-plus-trial` / `RUN_AI_PLUS_TRIAL`：仅运行 Plus 试跑；
3. `run-ai-flash-trial` / `RUN_AI_FLASH_TRIAL`：仅运行同样本 Flash 对照；
4. `ai-status`：只读查看计数、Token、金额与安全错误类别；
5. 远端人工全审 5 份 Plus 的结果；Flash 仅作受控成本/质量对照，不构成首版发布门；
6. 只有 Plus 通过机械门且零重大错误，才讨论 `expand-ai-plus`。该操作也只是入队；允许正式批量外呼前，仍须单独批准生产批次的请求数、Token、人民币上限与暂停/复核规则。

精确操作定义、确认文本和“不输出正文/原始响应/密钥”的边界见 [JD 技术提及远端运行与验收指导](JD技术提及远端运行与验收指导.md#首期-ai-语义解析受控试跑与发布)。
