# 确定性岗位族匹配运行与验收指导

本指南定义 JD 正式岗位族字段的固定处理链。真实岗位标题、JD 正文、证据片段、数据库连接串和运行时密钥不得写入 Git、CI、普通日志或聊天。

## 正式来源与边界

- 仅官方“程序&技术类”（当前 `official_category.id = "1"`）的规范化岗位 `title` 可进入岗位族匹配；不构造模型客户端、不读取百炼 Key、不发起模型调用。
- 人工审核的版本化词典含 13 个稳定岗位族。只匹配登记的完整字面别名：中文连续字面匹配；登记的 ASCII 别名按明确的大小写和标识符边界规则匹配。不做模糊匹配、分词、自动同义词扩展或语义推断。
- JD 正文、技术关键词、技术或 AI 结果、`projectName`、`objectName`、相似岗位和外部知识都不是正式来源，也没有回退资格。
- 已审核项目词典命中的完整项目片段只在其精确码点范围内被掩蔽；泛词不会因此被掩蔽。岗位族解析仅读取这些掩蔽范围，不读取项目归属结果或来源项目字段。
- 每个命中保留岗位族稳定键、命中次数、别名和 Unicode 码点区间。每份 JD 最多一个主岗位族：命中次数最多优先；相同时取最后结束的有效命中；仍相同时取 `family_key` 字典序最前者。

范围外的已知分类保存为 `out_of_scope`，分类未知保存为 `scope_unknown`，范围内空/无效标题保存为 `invalid_title`。范围内有效标题无命中保存为完成状态 `unclassified`。这些状态不等于同步失败，也不伪造主岗位族。

## 增量与重试规则

结果身份固定为：`title_identity + job_family_parser/dictionary identity + project_mask_parser/dictionary identity`。

1. 首次运行会为全部既有来源元数据建立观察记录，并为所有范围内的不同标题补齐当前身份结果，包括 `unclassified`。
2. 同一身份的重复运行不重复创建结果或证据；同标题的地点、工作性质等非标题来源变动仅建立新的观察记录并复用标题结果。
3. 每日同步只处理新标题、变更标题，或当前身份缺失的标题。词典/解析器或项目掩蔽身份更新会有意重新处理对应历史标题，旧结果和证据保持不可变。
4. 单个来源元数据的观察建档失败时，保留仅引用该来源版本、处理身份和固定安全错误码的审计，不记录标题或正文；只有该来源版本保持待处理，下一次固定运行可独立重试。单个已建立标题的解析或存储失败同样保留其标题身份的安全审计。两类失败都不会被改写为 `unclassified`，也不会阻断其他标题、项目、学历、年限或技术阶段。若任一审计存储本身不可用，固定操作会安全报告该阶段错误，但同批其他独立标题和后续确定性阶段仍继续尝试；不会伪造已记录的审计事件。

人工发现错误时，只能修复来源标题、发布新的版本化词典规则或安排重试；首期不提供单标题人工覆盖。

## CVM 受控操作

远端使用既有 root-owned 固定入口：

```bash
sudo /usr/local/sbin/mrolescope-operations run-pending-analysis
```

该入口启动固定 worker 子命令 `analyze`。它独立尝试项目、岗位族、学历、工作年限和已发布技术词典分析；岗位族本身没有 Qwen 或其他模型调用。任一阶段故障不会阻止其余独立阶段被尝试，但整个固定操作会以安全的失败状态报告发生故障的阶段。

首次部署后由运维人员人工运行一次该入口建立历史标题基线。之后既有每日同步的下游 best-effort 分析会处理新增或变更标题，无需增加 timer。不得用 `analyze-ai`、AI 试跑、扩展或发布操作建立岗位族基线。

## 无正文验收

1. 首次运行后，当前身份的岗位族完成结果数应覆盖所有范围内不同标题身份；其中允许存在 `unclassified`。
2. 紧接的第二次运行不应新增岗位族结果；同标题的非标题元数据变动也不应新增标题级结果。
3. 新标题或变更标题只新增相应标题的一条当前身份结果；岗位族或项目掩蔽词典/解析器身份更新时，历史标题重新处理是预期行为。
4. 可检查聚合处理数、状态、版本、摘要、岗位族稳定键、命中别名和码点区间，以及稳定安全错误码；禁止输出岗位标题、JD 正文、模型输入/输出、API Key 或数据库 URL。
