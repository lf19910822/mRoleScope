## 二、每日同步计划与任务流转



### 固定运行计划


| 项目     | 当前实现                                                        |
| ------ | ----------------------------------------------------------- |
| 定时     | 每日 02:00（Asia/Shanghai）                                     |
| 补跑     | `Persistent=false`；机器停机错过的时点不自动补跑                           |
| 一轮重试   | 初次失败后 15 分钟重试；再失败后 45 分钟重试；最多 3 次                           |
| 缺失岗位复查 | 对本次列表未出现的开放岗位逐个、低并发详情复查；明确不可用路径最多 3 次                       |
| 下游解析   | 源同步成功后以 best-effort 触发固定 pending-analysis；其失败不回滚已经成功发布的来源同步 |




### 单次运行的事实链

```text
定时器/受控手工运行
  → 来源列表与详情采集、格式验证
  → 对“列表缺失但此前开放”的岗位做详情复查
  → COS 归档经过验证的本批来源证据
  → PostgreSQL 原子发布：运行、观测、可见期、正文期、审计
  → best-effort 触发待处理的确定性 JD 建模
```

缺失复查有三种业务结果，图表应保留其区别：


| 复查结果           | 岗位处理                                          | 可作为“下线”统计吗？ |
| -------------- | --------------------------------------------- | ----------- |
| 详情明确不可用        | 关闭可见期，记录 `detail_definitively_unavailable` 证据 | 可以          |
| 详情仍可用          | 保持开放，并清除本次缺失状态                                | 不可以         |
| 网络、限流、HTTP 或未知 | 标记为待下一轮重新验证，不进入人工确认队列                         | 不可以         |


截至数据截点：当前 `open_missing` 为 **0**；历史已确认关闭的 4 条可见期均为 `detail_definitively_unavailable`。这使“确认关闭”可以成为正式图表指标，但“列表本次未出现”只能作为来源观测差异，不能直接当作关闭。

## 五、为图表一期保留的实现能力

1. **可重放的日差异。** 每次成功发布保留岗位观测与正文版本引用，因此可以按指定日期的最后成功快照重建列表增减、正文变化及在招盘面。
2. **可解释的关闭事实。** 可见期保留开启、最后出现、首次缺失、关闭时间、关闭原因和详情复查证据；图表可严格区分“来源列表差异”和“确认下线”。
3. **版本化的字段事实。** 学历、年限、技术词、项目标签都连接到具体正文或标题身份，以及解析/词典版本。规则升级造成的重算可以在数据层追溯，避免误读为岗位需求突变。
4. **审计与正式数据分层。** AI 原始输出与语义候选有受控审计路径；确定性正式字段不读取模型 API Key、不向外部模型发送 JD，也不以 AI 结果补缺。图表可先交付稳定的正式层，再选择性增加“实验/质量”视图。
5. **增量处理。** 新增或正文变更的 JD 会进入 pending pipeline；未变更正文复用已有不可变解析结果，不需要每日全量重新解析。



## 六、图表一期可做与暂不应做的范围



### 已具备数据基础，建议由大计划守护者在一期中选择

- 当前在招盘面：确认开放数、确认关闭数、最新来源列表数、列表差异待复查数。
- 日趋势：来源列表岗位数、日新增观测、日列表未出现、正文版本变化、确认关闭数。
- JD 正式字段的当前分布：学历、最低工作年限、正式技术词覆盖、项目命中 / 未识别。
- 项目维度分组：明确游戏与来源方向 / 预研标签分开；未识别保持可见。
- 数据质量与新鲜度：最新成功时间、详情成功 / 失败、当前解析覆盖、结构一致性检查。



### 有数据但需明确口径后再画

- 历史“在招数”：使用每个数据日最后成功快照的来源观测，还是使用经过后续详情证据修正的可见期回放，二者会得到不同但都合理的数。产品必须选择并明确命名。
- 多标签项目统计：使用唯一岗位数还是岗位—项目关系数；首期可默认唯一岗位数，并在出现多标签时提供切换或注释。
- 学历/年限的“未设置”：应显示为独立分组，不能与解析失败或数值 0 合并。



### 当前不具备可信比较条件

- 月、季度、年度趋势，以及同比 / 环比：只有 7 个数据日，不足以覆盖完整对比周期。
- AI 对岗位语义的正确率、熟练度和要求关系：候选/审计层尚未发布为正式字段，不能与确定性覆盖率混画。

在对比周期缺失时，接口和页面应返回或展示 `insufficient_history`**（历史不足）**；不要以空数据生成 0、也不要自动补齐不存在的上期。

## 七、请大计划守护者裁决的图表一期问题

1. 首期主视图的叙事是否采用“每日来源变化 + 当前在招结构 + 数据质量”三段式，还是优先某一个维度？
2. 历史在招曲线采用“当日来源快照”还是“可见期回放”的口径？建议首期采用前者，并把确认关闭作为独立事实展示。
3. 是否将学历、年限、技术词、项目标签均展示为“有值 / 未设置”双层比例，以避免把无值误读为处理失败？建议：是。
4. 项目筛选和图例是否坚持“明确命名游戏”“来源方向/预研”“未识别”三个并列分组？建议：是。
5. 图表一期是否完全排除 AI 语义正确率与候选词细节，只保留可选的“候选词治理容量”运维指标？建议：是。
6. 数据历史尚短时，月 / 季 / 年与同比环比的产品占位应显示“历史不足”还是暂不展示？建议：显示“历史不足”，这样既不伪造 0，也为后续自然积累预留固定接口。
