# 问题描述

目前我们的系统能够绘制曲线，总结数据。但是使用起来较为困难，无法将用户抽象的需求简单映射为图表。
举例：用户想知道“MHY使用哪些后台数据库？使用哪些模型训练工具？有哪些正在进行的项目？”
可以通过画出我们的线性表来回答这些问题，比如配置不同项目/不同技术关键词 的曲线。但是目前配置曲线的过程较为繁琐，拟定让AI来自动识别用户需求，并自动配置/画出曲线。

# AI职责

AI负责：
1. 理解并鉴别用户意图
2. 根据用户意图抓取必要参数。比如用户想要知道”目前投入最多的项目“，应该根据项目岗位数量排序后再绘制曲线。
3. 给出一份曲线配置草稿。草稿以列表形式展现AI想要绘制的曲线，最多8条。
4. 给出一小段解释说明，解释为什么要画这些图表。

后续用户可以针对草稿手动添加/删除/修改，并应用。应用后跳转到曲线展示面并绘图。

# 调研点
以下是我现在可以想到的调研点：
1. 可以开发本地MCP server，将数据库各部分数据/曲线绘制/筛选列表 的各个功能打包为AI可以调用的方法，帮助AI理解数据库数据。此处的要点是必须让AI理解岗位的先后关系，哪些是最新岗位数据，哪些是历史数据。
2. 可能需要AI可调用的数据处理工具，比如根据某个值进行排序/聚合。
3. 总的来说，这项功能涉及到AI 数据检索/处理。我们可以先试试看已有的QWEN，如果效果不好，再申请DEEPSEEK或更强模型。
4. 评估一下是否应该引入RAG。
5. 应该留下审计内容，帮助我们优化AI调用逻辑。但同时也要注意容量警告，不能因为审计造成容量灾难/等待时间过长
6. 评估是否应该引入成熟的AI框架，比如 langchain,langgraph。例如我们编写了MCP，function，需要AI自动发现并调用工具，输出调用了哪些工具/工作流程是什么。这可能需要成熟框架的支持，我们自己实现有些困难。

# 要求
1. 速度要快，AI的本职是调用我们的方法理解/作图，本身不承担作图职责，不应该有太复杂的工作流，也不应该耗时过长
2. 控制成本
3. 要有初步的放入侵措施，比如限制上下文长度之类的。

# 当前岗位交叉统计（2026-11-27）

- 当前有效岗位支持技术关键词、项目、岗位族和地点的交叉计数与范围内排名；同维度支持并集和交集，跨维度支持交集，明确排除条件不被丢弃。跨维度并集和历史交叉统计暂不支持；历史问题给出标明当前口径的参考。
- 同一岗位在总数中去重；正向条件由同一条有效记录满足，任何当前有效记录明确命中排除条件时不能用其他记录绕过。岗位族默认包含主、副，明确要求时仅看主岗位族。涉及技术筛选时，缺少可用技术分析的岗位静默跳过；不涉及技术筛选的查询不因此排除岗位。未能判断的排除条件不当作确定符合。
- 类别在一致性快照中展开，先在完整范围内统计排序，文字默认前 8，可按要求展示更多或全部。技术关键词只表示岗位内容中识别到该词。模型读取有界聚合数据；数量、排名和解释中的事实由程序核对并生成。
- 趋势图继续显示各维度的独立曲线，最多 8 条，不代表交集或并集。统计与图表独立交付；范围不符或正式值无法确认的草稿被阻断。新请求期间旧草稿可继续应用，若无新的合格草稿则保留并标记为上次结果。
- `/api/v1/job-trends/ai-draft` 保持原有 NDJSON 事件类型；`query_current_job_statistics` 操作事件不暴露参数，较长排名通过连续 `assistant_message` 事件交付，旧事件仍可消费。模型及公开事件不接收岗位正文、岗位 ID、SQL 或凭据。
- 验证使用隔离的 PostgreSQL 16 合成数据、确定性模型提供器和离线测试，没有运行真实模型评测。1,000 条当前岗位的合成样本中，上海与技术关键词交集并按岗位族分组得到 500 条：一次端到端读取约 51 ms，`EXPLAIN ANALYZE` 执行约 25 ms；该结果不能代表生产数据规模或实际服务延迟。一致性测试覆盖查询期间发布切换，分页测试覆盖超过 100 项及中断。
- 本次验证：`go test ./...`、前端 31 个测试文件及构建通过；交叉统计数据库用例在隔离测试库单独运行。默认 Go 测试未配置 `TEST_DATABASE_URL`，其他依赖该变量的数据库集成用例按原有规则跳过；未使用运行实例凭据。

# 已落地的实现约束（2026-11-18）

- 入口只在趋势页；用户直接输入自然语言即可生成待确认草稿，AI 只选择曲线，完整点位仍由 Serving 在应用后提供。
- 合同版本为 `ai-trend-draft-v1`：每次请求最多 20 次工具调用、每次最多 100 个候选、批量工具最多 8 个候选、草稿最多 8 条曲线、非法 AI 参数最多修正 3 次。
- 工具只能从注册白名单中选择：类别/正式值、排序、趋势摘要、事件摘要、批量读取和草稿校验。工具返回有限摘要，不返回 SQL、JD 正文、凭据、内部发布标识、完整日点或模型逐字推理。
- 非法 AI 参数才反馈给 AI 修正；参数合法但 Serving/后台失败时标记失败并继续独立步骤，不自动重试 AI。用户停止时保留并标记上一份草稿，已收到的本次回复可能不完整。
- 草稿默认勾选扩展推荐；支持别名、有限相似匹配、排除词、多维度候选、项目与全局技术的最大努力结果。重复曲线按维度、正式值、比较条件和岗位族口径合并；“仅主岗位族”和“含副岗位族”保持分开。
- 新请求独立处理；成功才替换旧草稿，失败或停止保留旧草稿。应用后图例只显示正式名称，扩展/全局提示留在 AI 回复中。
- 流式接口是一次提交对应一条 HTTP NDJSON 流，事件只展示操作名称、状态和过滤后的参数；完成、部分成功、失败、用户停止使用独立终止事件。操作记录默认折叠，只在当前趋势页保留。
- 审计只保存不可逆哈希、状态、错误码、调用/令牌/耗时和草稿数量等聚合字段，保留 30 天并限制 10,000 条；清理失败只告警，不阻断用户结果。
