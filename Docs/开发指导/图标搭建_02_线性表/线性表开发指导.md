# 开发目标

本期拟定开发一个泛用的折现图，用来统计各个维度的数据。该功能与 岗位筛选 并列，放在左侧导航栏中。拟定需求如下：

## 时间范围

拟定允许设定 本周，本月，本季度，本年，全部历史 五个时间维度。
以天为基本单位。
其中的周，月，季度，年 都应该符合真实日期，而非简单的时间加减。

每天的点表示当天快照中匹配的独立 JD 数；不能把每天的存量相加，否则同一岗位会被重复累计

某日数据缺失可以静默放弃，不能补0，不要影响图表展示。保持真实日期间距；缺采为空，完整采集后无匹配才是零

## 维度

1. 技术关键词

统计某个技术关键词的数量。
例如：用折线图标识技术关键词 Kubernets 的数量变化趋势。
通过技术关键词词典 获取与该关键词有关的JD，并计数。

1. 岗位族

统计某个岗位族的数量。
例如：用折线图标识 岗位族 运维 的数量变化趋势。
这里支持配置：
    1. 只统计主岗位族
    2. 除了主岗位族，也统计副岗位族。例如 主岗位族是 运维 的JD有3个，副岗位族中包含 运维 的JD有 10个。那么这项配置针对 运维 应该返回 13.

1. 范围学历

统计某个范围学历变化的折线图。 例如：用折线图标识 >=本科 JD 数量的变化趋势。

注意这里和工作年限一样支持配置：>, <, >=, <=, ==。默认==

1. 项目

统计某个项目的数量。
例如：用折线图标识 原神JD 的数量变化趋势

1. 工作地点

统计某个工作地点的数量。
例如：用折线图标识 上海JD 的数量变化趋势

1. 工作年限

统计某个最低工作年限的数量。
例如：用折线图标识 一年以上工作经验JD 的数量变化趋势
注意这里支持逻辑配置。比如 “最低年限＝1”和“最低年限≥1”是两种统计，后者会包含要求 3 年、5 年的岗位。拟定支持 >, <, >=, <=, ==

## 图表细节

1. 图表要有高互动性。支持鼠标滚轮放大/缩小维度。鼠标点击拖拽X轴向前，向后。注意是图内拖拽，不是图边缘滚动条拖拽。本周，本月，本季度，本年不支持开放这两个功能，固定x轴和Y轴。但是 全部历史，支持这两个功能，提供高互动性，高自由度的查看
2. 图表的每个节点后续都要支持下钻。这里先预留点击反馈效果。后续点击图表节点，要跳转到相应的岗位列表中。
3. 图表展示面要大，展示维度支持自由配置。同一张图表中最多支持8条异色折线图。注意：同一维度可以有多条折线图，比如同时启用 Kubernets 和 MYSQL 的技术关键词折线图。这同样意味着Y轴要支持自由缩放，不同维度的数据Y轴差异可能很大。八条线建议共用一个 Y 轴。 它们单位都是岗位数。数量差异大时，用图例隐藏、聚焦曲线和手动范围查看细节；不宜给每条线配一个独立坐标轴
4. 图表折线图要略微圆润，不要过于尖锐。
5. 图表展示性能要高，应尽量复用已经开发完成的数据结构和逻辑，比如已有的岗位筛选功能。如果发现了明显的性能问题，可以考虑开发新的图表展示层 SERVING,将一些快照任务纳入每日同步中。但这同样也要注意容量开销，只有性能问题极其严重的时候才能让我批准采纳。

## 折线图功能扩展

1. 折线图日期范围支持自定义，放在 全部历史 右边，支持用户自定义图表的起止时间。自定义图表和全部历史一样支持鼠标拖拽/放大。
2. 当前折线图需要支持下钻，依据图表的筛选条件下钻到具体岗位JD。大致要求如下：
    1. 岗位JD详情展示面复用 岗位筛选 的模板
    2. 通过弹窗打开对应下钻点的岗位列表，列表明细简单一些，仅保留岗位名称即可，要紧凑。弹窗支持上拉下拉，名称模糊搜索。
    3. 岗位列表中的每一条岗位作判断：
        1. 如果该岗位截至目前依然存在且没有改动，标注：仍有效，提供 查看最新
        2. 如果该岗位截至目前依然存在，但是有修改，标注：有改动，提供 查看历史JD 和 查看最新JD
        3. 如果该岗位截至目前已经消失，标注：确认下线，提供 查看历史JD。
3. 查看历史JD，应该从数据库SCD2层级找到该JD对应时期的历史数据，不应该展示最新JD。不应该新增serving表格。
4. 注意性能要求，聚合，响应速度要快。

4. 时间窗口对比
例如选择：
本月 vs 上月
Go：+18 个岗位，+12.5%
后端岗位族：-7 个岗位，-4.1%
必须遵守两个规则：
- 两个窗口长度一致
- 数据覆盖不足时只显示“数据不足”，不伪造百分比
第一版甚至可以先在前端基于现有曲线点计算，之后再考虑服务端聚合。
