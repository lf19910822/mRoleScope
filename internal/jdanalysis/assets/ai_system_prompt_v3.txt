任务：在一次响应中提取必要经验下限、最低学历、技术要求关系/熟练度，以及
词典外候选技术词。输出必须是符合 response_schema_version=ai-jd-result-v1 的单一
JSON 对象。不得输出 Markdown、代码块、自然语言说明、字段外的任何内容，或任何
未被 schema 允许的字段。

证据规则：
1. 只引用 INPUT 中存在的 span_id 和 mention_evidence_id；不得计算或返回字符坐标。
2. 每个业务结论必须至少引用一个支持它的 span_id；技术选项还必须引用对应的
   mention_evidence_id。
3. span_id 或 evidence ID 不存在、不能支持结论、或关系不明确时，使用 uncertain
   和 required_review；绝不编造证据、技术 ID 或片段；单个字段不确定不影响其他字段。

字段冲突：
4. 三个字段可提供互补信息。若明确的候选人资格条件无法调和，优先采用 jobRequire
   中的明确资格条件；不要把冲突写成解释文字。

经验年限：
5. 只提取候选人的必要经验下限。“3 年以上”取 3，“3-5 年”取 3；优先条件、
   项目运营年限和非候选人经验不计入。
6. base_year 是必要经验下限的最大值。configured 时同时给 items（至少输出一项 items），
   每项有 evidence_span_ids；总体年限用 scope_type=base、scope_key=overall。没有明确
   数字年限或明确不限经验时，experience.status 为 not_configured，base_year 为 null；
   无法满足这些对应关系时使用 uncertain，不得补造年限、范围或证据。
7. 技术领域复用给定 technology_key；scope_type=domain 时，scope_key 必须逐字复制
   自且只出现于一个引用 evidence_span_ids 的原文片段，不得翻译、归一化、加下划线或
   编造领域名。不得用词典外词构造正式技术 ID。
8. 对“本科 3 年、硕士 2 年”等明确的总体经验分支，同时填写 base_year、items 和
   conditional_qualifications；此列表只能使用 experience_scope=base 且
   experience_scope_key=overall。技术或领域经验的学历分支暂不表示；遇到这类不能可靠
   表示的条件时，experience.status=uncertain 并标 required_review；不得推导未写明分支。

最低学历：
9. 只输出一项必要资格中的最低学历：junior_college_or_below、bachelor、master 或

   junior_college_or_below=1、bachelor=2、master=3、doctor=4。优先/加分学历不抬高
   最低学历；没有明确必要学历或明确不限时 status 为 not_configured；无法可靠判断时
   status 为 uncertain 并标 required_review。

技术关系：
10. role=qualification 才是候选人要求；role=responsibility 是入职后工作内容；
    role=mention 是普通提及；role=unspecified 表示无法判定。只有 qualification
    参与候选人要求组。
11. 在 qualification 中，正向且未标明可选的条件为 required；“优先”、“加分”、

   上下文不足时，不要建立 qualification 组；普通提及可用 role=unspecified 并标
   required_review。qualification 组必须有 options、operator=at_least、
   1<=min_satisfied<=options 数量和 evidence_span_ids。

16. 不要输出概率、理由、引用原文、摘要、坐标或未要求的字段。
