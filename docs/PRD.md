# MHY JD Observatory — 产品需求文档

## 目标

MHY JD Observatory 是一个非官方的米哈游「程序&技术」社会招聘岗位观察站。它按固定范围、固定周期采集公开 JD，以可解释、可复现的规则处理数据，并向招聘者与求职者展示当前分布、历史变化与正文版本对照。

首期的可信度优先于图表数量：任何图表和岗位页都必须能追溯到已发布采集批次、规则版本和公开来源正文。

## 用户与价值

- 求职者：查看技术岗位的范围、年限要求、技术关键词和正文演变。
- 招聘从业者：观察岗位构成与相邻周期的真实变动。
- 维护者：以受保护的 CLI 触发采集、检查失败和更新词典/规则。

访客匿名只读；首期没有账号、收藏、简历上传、个人匹配或公开管理后台。

## 范围

首期固定为公开 API 中 `competencyTypes=["1"]`、`hireType=0`、`channelDetailIds=[1]` 返回的岗位。岗位身份为 `source_company + source_job_id`，标题只用于展示，不能作为主键。

默认每周一 08:00（Asia/Shanghai）运行；内部保存 UTC，页面展示北京时间和明确采集时间范围。调度参数、并发、超时、重试和采集筛选配置均可配置。

## 数据正确性要求

1. 成功批次永久保留完整、可校验的压缩原始归档；数据库文本去重不得破坏任一批次的完整还原能力。
2. 列表分页、详情抓取、总数、唯一 ID、结构变化与归档校验任一异常，批次均不得发布；站点继续显示上一次成功版本。
3. 同筛选条件的相邻成功批次才可比较。筛选配置或来源口径改变必须成为可见断点。
4. 解析规则、词典和分类体系均版本化。规则升级不覆盖旧结果；趋势图使用相同规则重算，或清晰标示不可比。
5. AI 仅可作为可关闭的歧义辅助。计数、聚合、版本判断和文本 diff 由确定性程序执行。

## 页面与图表演进

基础页面为总览、岗位列表、岗位详情和版本对照。图表分五个独立验收周期交付：

1. C1 岗位变化构成。
2. C2 年限进度条。
3. C3 技术岗位版图。
4. C4 岗位方向 × 技术关键词。
5. C5 JD 修改对照。

首个可发布图表之前，页面显示真实发布批次元信息与明确标记的空态；不使用伪造生产指标或历史 JD。

## 非功能要求

- 后端以 Go 模块化单体实现，Python 仅负责采集适配。
- 生产运行在用户个人账号的第三方云环境；不使用雇主网络、凭据或基础设施。
- 全部公网流量经 HTTPS；数据库和对象存储管理权限不暴露给浏览器。
- 前端采用 Vue 3、TypeScript、Vue Router、Naive UI、ECharts，桌面与手机均可用；遵守键盘访问、可读对比度与减少动画偏好。
- 站点明确标示为非官方项目，提供公开官网来源，不使用官方 Logo、角色或游戏 UI。

## 成功标准

M0 完成时，个人环境可启动 API 和 PostgreSQL，迁移可重复执行，离线采集 fixture 可生成并校验任务目录/manifest，且健康检查可用。后续每个图表周期必须分别具备数据定义、API、前端空错加载态、测试和可审阅演示。

## 已知待定项

- 正式名称、域名、云厂商、部署区域和上线日期。
- 个人是否已有域名。
- 生产对象存储厂商与对应 SDK/兼容性。
- 词典初版、内部岗位分类体系和人工复核流程。
