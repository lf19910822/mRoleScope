# ADR 0001：采用 Go 模块化单体与 Python 采集适配器

状态：已接受（2026-10-20）

## 背景

首期需要 API、worker、数据处理与单一公开来源采集，但访问量、规则复杂度和云预算均不支持过早引入微服务、消息队列或缓存集群。

## 决定

以单一 Go 模块实现 Gin API、worker 和共享领域代码，作为独立进程部署。Python 保留为零第三方依赖的公开 API 采集器，只写版本化任务目录和 manifest。Go 通过固定可执行文件与参数列表启动它，绝不通过 shell 拼接命令。

## 后果

减少初期部署和调试成本，采集仍可复用现有脚本的成熟 HTTP 行为。将来仅当可观察到独立扩展、可靠性或团队边界需要时，再从模块边界拆分进程或服务。
