# 备份、恢复与回滚

## 备份对象

- PostgreSQL：每日逻辑备份或经验证的物理备份，包含迁移后的全部业务表。
- 成功批次归档：对象存储版本/冗余策略和定期可读性校验；它不是数据库备份的替代品。
- 配置：仅备份非秘密配置。密钥由个人账号下的密钥管理保存。

## 恢复演练

1. 在隔离环境恢复指定时间点的 PostgreSQL 备份。
2. 按 `collection_runs.archive_uri` 下载一个成功批次，核对 archive/manifest SHA-256。
3. 重建该批次的 `run_jobs` 映射并核对计数。
4. 运行只读 API 核对当前发布批次与历史批次可访问性。
5. 记录耗时、缺失项和修复措施。

## 回滚

应用回滚不删除批次。若当前发布批次被发现不可靠，在审阅后以短事务将 `publication_state.published_run_id` 指回上一个已验证成功批次，并保留故障批次、日志和归档用于诊断。数据库迁移的 down 操作只用于经过备份与演练的维护窗口，生产故障优先采用前向修复。
